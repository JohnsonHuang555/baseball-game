# V2 觀戰：已結算比賽的動畫重播（Read-only Replay）與 schemaVersion 6

Phase 5B 讓玩家觀看自己球隊已經打完的自動比賽（以及最近一次晉級挑戰賽），用 V1 的球場動畫逐球播放。觀戰是**唯讀**的：只看、可以控制節奏，不能改變結果、不會重新結算、不會重複發獎，也不會寫入存檔。

## 1. 現有程式的分析

| 問題 | 結論 |
|---|---|
| V1 怎麼逐球推進 | `gameScreen.loop()`：可能先打開指令面板讓教練下指令（`game.issue`），再 `game.step()` 推進一球，最後 `animate(events)` 依序播完這一步的事件 |
| 動畫與邏輯的耦合 | `animate`、`renderBoard` 直接讀即時的 `game` 狀態；決策面板、計量條、教學、自動存檔（`onProgress`）都在 `showGame` 同一個閉包。所以觀戰不重用 `showGame`，只重用下面的元件 |
| FieldRenderer、PitchCam | 可以各自建立與播放，但原本沒有取消或銷毀：補間動畫會用 `requestAnimationFrame` 跑到結束。本階段加了 `cancel()`（世代代號，舊動畫下一幀直接結束、不再繪製），V1 不呼叫，行為不變 |
| `setup + commands` 夠不夠 | 夠：規則與兩邊的 AI 都是確定性的，V1 的 `replay()` 就是這樣重播。但 `replay()` 會丟掉 `issue()` 本身產生的事件（換投、代打、故意四壞），觀戰需要它們，所以自己逐步推進並收集 |
| V1 的速度與暫停 | 速度：每段動畫時間除以 `speed`（1×／2×／4×），一般時刻再快 1.4 倍。暫停：在球與球之間打開指令面板 |
| Replay 保存量 | `RETENTION_CONFIG.replays = 3`。單場約 6～8 KB（平均 6.9 KB），3 場約 20 KB，約占 96 場離線結算後存檔（51 KB）的 40% |
| 獨立開關 | 可以：做成蓋在 V2 畫面上方的子畫面，不動 V2 的分頁、戰報對話框與草稿 |
| 重播時要禁止什麼 | 鍵盤用 `setKeys` 換成觀戰專用的按鍵、關閉時還原；音效沿用使用者的開關設定（`sound.ts` 的設定）；觀戰完全不經過 controller，不寫入存檔 |

## 2. 架構

```
application/replayPlayer.ts   不碰 DOM
  buildTimeline(replay, expected?) → ReplayTimeline
  ReplayPlayer（狀態機）+ ReplayPresenter（介面）
ui/replayView.ts              動態載入
  openReplayViewer() → 子畫面、Presenter 實作、ReplayStage（Canvas）
ui/playAnimation.ts（V1 共用）  節奏、事件分類、音效選擇、爆炸框圖形
```

**時間軸（`buildTimeline`）**
- 驗證 Replay 結構與規則版本，深拷貝後交給 V1 的 `Game`，用跟 `replay()` 一樣的時機下指令，逐步推進。
- 每一步產生一格：這一步的事件（包含指令產生的事件）、這一步開始時的投手、是不是關鍵時刻、這一步結束後的完整狀態（比分、每局比分、安打、失誤、局數、出局、好壞球、壘上、打者、投手、佈陣）。
- 開啟觀戰時就一次算完整場，平均 254 格、約 2 ms。所以每次觀看都完全相同；跳到結束、重新播放只是移動位置。以後要做逐局跳轉，用格的局數找位置就行。
- 算完會跟戰報摘要核對比分、勝負、局數，不一致丟 `mismatch`，不播放不可信的內容。
- 任何問題（資料損壞、指令不合法、規則版本超出 1～`RULES_VERSION`、超過步數上限）都只會丟 `ReplayError`。

**播放器（`ReplayPlayer`）**
- 狀態：`idle → playing ⇄ paused → completed`，另有 `error`、`disposed`。
- 操作：`play / pause / resume / setSpeed / restart / skipToEnd / dispose`。
- **只有一個播放迴圈**：每次開始播放都換一個新的迴圈代號，舊迴圈發現代號不同就停。
- **位置**：只在一格完整播完才前進。暫停、跳過、重新播放、關閉都用 AbortController 中斷這一格，畫面回到已經播完的位置；繼續時這一格重播一次，模擬狀態不會因為暫停而多走或少走。
- **速度**：用函式讀取，播放中切換時下一段動畫就生效。速度影響所有等待時間與球場動畫的長度，不只是文字。
- **預設 2×**：V1 一般比賽是 1×，但觀戰看的是已經打完的比賽，1× 一場要十幾分鐘。

**畫面（`replayView.ts`）**
- 比分條沿用 V1 的樣式，下面依序是球場、打者與投手、最近一球、逐球紀錄，底部是控制區。
- Presenter 是 V1 `animate()` 的觀戰版，球場、投球視角、爆炸框大字、全壘打數據卡、音效都用 V1 的元件與規則。差別只在狀態一律來自時間軸，不讀即時的 `Game`。
- 一格結束時，畫面對齊模擬的狀態。打完一球結束半局時，先顯示得分與三出局，再換成下個半局。
- 唯一的隨機是 V1 球場上界外球飛出去的方向：純視覺，不影響任何狀態。

## 3. 正確性與副作用

- 開啟觀戰時，從畫面上的球團複製一份 Replay 與戰報摘要。之後就算存檔被更新、這場 Replay 被新的結算擠出保存清單，已經開啟的畫面仍然播完。
- 時間軸只看 Replay 裡的快照：之後的升級、釋出、晉級都不影響舊比賽。已經釋出的球員仍然會出現在 Replay 裡。
- 觀戰不經過 controller、不呼叫任何寫入。測試會比對觀戰前後的存檔原文，連 revision 都沒變。
- **觀戰期間的自動結算**：照原本的設計進行。首頁計時器、回到前景、手動更新都會照常結算到期的比賽，觀戰畫面不跟著球團狀態更新。測試會把「觀戰＋結算」跟「只結算」的存檔逐字比對，兩者相同，代表觀戰本身沒有任何副作用。
- 其他分頁修改球團時，觀戰畫面不受影響。關閉觀戰後，首頁本來就會跟著 controller 的最新狀態重畫。
- **錯誤處理**：資料壞掉、版本不相容、結果對不起來時，顯示可以理解的錯誤，可以返回，V2 照常運作、不修改存檔。播放中畫面出錯時，停在 `error`。

## 4. 入口與返回

- **戰報**：有完整重播的場次（最近 3 場）有「觀看比賽」；其他場次說明完整重播已不再保留，仍顯示文字戰報。
- **首頁**：「觀看最近比賽」（最近一場有保留完整重播才能按）。
- **晉級挑戰**：挑戰結果對話框有「觀看挑戰過程」，首頁聯盟卡片有「觀看上次晉級挑戰」。
- **返回**：關掉子畫面，回到原本的分頁；戰報對話框、挑戰結果對話框都還在，陣容與戰術草稿不受影響。沒有新增底部分頁。

## 5. 生命週期與效能

- `close()` 會依序：
  1. 停止播放器（中斷進行中的一格）。
  2. 取消球場與投球視角的動畫。
  3. 清掉所有計時器（大字、全壘打數據卡）。
  4. 移除 `visibilitychange` 監聽器與 ResizeObserver。
  5. 還原鍵盤快捷鍵，移除畫面。
  之後的任何 callback 都不再操作 DOM。
- **背景化**：頁面被隱藏時自動暫停，不自動恢復。瀏覽器本來就會暫停背景的 `requestAnimationFrame`。
- **觀戰畫面是動態載入的獨立 chunk**（`replayView-*.js`，18 KB，gzip 後 7 KB）。放置結算、Headless MatchRunner 不會載入任何畫面或 Canvas。
- 96 場結算的耗時維持原樣（約 135 ms）。
- 重複觀看同一場：每次都重新建立時間軸，關閉後全部釋放，不會累積。

## 6. 晉級挑戰的 Replay（schemaVersion 6）

- **新增欄位**：`challengeReplay: { seq, matchId, replay } | null`，只保留最近一次挑戰（成功或失敗都存，約 7 KB）。驗證規則：`seq` 一定是最近一次挑戰的序號。
- `applyChallenge` 在記下挑戰結果時一起存入。
- **冪等不變**：重送同一個請求，回傳原本的結果，Replay 也不會變；另一個分頁拿舊畫面送出的請求照樣被拒絕。
- 觀看挑戰賽用挑戰紀錄的比分核對，不會重新挑戰、不會重新發獎、不會改聯盟進度。
- **遷移**：
  - V5 → V6 只加上 `challengeReplay: null`，其他欄位照搬。舊的挑戰賽本來就沒有 Replay，不會補產生。
  - V3、V4 依序經過 V4、V5 再升到 V6。
  - 原始文字備份到 `…backup-schema5`，沿用既有的安全順序與「不覆寫有價值的備份」規則。
  - V5 的 fixture（`club-v5-phase5.json`）是用 Phase 5A 的程式（`origin/main`）實際跑出來的：324 場、招募 2 次、釋出 1 次、挑戰 2 次。
  - 還開著 Phase 5A 程式的分頁讀到 6 會判定版本不相容，停止寫入（跟之前每次升版相同）。

## 7. 支援的動畫事件

| 事件 | 呈現 |
|---|---|
| 投球（球種、軌跡）、好球、壞球、界外、揮棒落空 | V1 球場投球動畫＋投球視角小窗＋好壞球燈號＋音效 |
| 一壘、二壘、三壘安打 | 擊球飛行、野手追球、跑者推進、文字 |
| 全壘打 | 飛行、爆炸框大字（陽春／兩分／三分／滿貫）、擊球數據卡、歡呼音效 |
| 一般出局（滾地、飛球、平飛、犧牲打）、三振（含站著被三振） | 守備員接球、K 大字 |
| 雙殺 | 雙殺大字與守備記號（例如 6-4-3） |
| 跑者推進、得分 | 跑壘動畫、得分大字、比分條即時累加 |
| 盜壘 | 跑壘動畫與文字 |
| 失誤 | 失誤大字 |
| 換投、代打、代跑、守備替換 | 文字提示（紀錄與最近一球），**沒有專屬動畫**（V1 也只有文字提示） |
| 半局結束 | 三出局、文字分隔線，接著換到下個半局 |
| 比賽結束 | 球場上蓋一層結果：勝敗、比分、每局比分與 R／H／E |

**沒有做的**：
- V1 比賽中的羈絆列與換人時的羈絆提示。
- V1 電腦版的雙欄打線與完整記分板。
- 球員頭像。

## 8. 保存策略

- 一般比賽仍然只保存最近 3 場完整 Replay（沒有改上限），其他場次只有摘要，仍然可以閱讀。
- 存檔大小：
  - 96 場後約 51 KB（其中 Replay 約 20 KB）。
  - 滿員 30 人約 61 KB。
  - 最高聯盟、長期遊玩、含挑戰 Replay 約 70 KB。
- 沒有加入 IndexedDB、Supabase 或其他儲存方式。

## 9. 限制與後續（Phase 6 候選）

- 沒有任意時間軸拖曳，但時間軸已經有每一格的局數，可以加「跳到第 N 局」。
- 換人沒有專屬動畫；觀戰也沒有 V1 的羈絆列與頭像。
- 觀戰期間背景結算若擠掉了這場的 Replay，關閉後就不能再看這一場（摘要還在）。
- **可以考慮的互動**（都必須維持不改變結果）：
  - 精彩片段（只播得分與全壘打）。
  - 逐局跳轉。
  - 觀戰時顯示雙方羈絆。
  - 分享某一場的連結（需要雲端，不在本階段）。
- 可以改變結果的即時戰術、九局下接管，需要另一套「可操作比賽」的設計，不屬於觀戰。
