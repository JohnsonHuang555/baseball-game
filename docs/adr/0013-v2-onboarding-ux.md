# V2 新手引導、首頁資訊層級、目前建議與 schemaVersion 8

Phase 6A 不加新的遊戲系統，目標是讓第一次玩 V2 的人在 10 分鐘內，靠實際操作理解：自己是球隊經營者、比賽會自動進行、可以看直播、比賽產生資金與經驗、資源可以培養球員、陣容會影響之後的比賽、晉級聯盟是長期目標。

## 1. 修改前的主要問題

實際建立新球團、在 390×844 與 1366×900 看首頁後，列出最大的 5 個問題：

1. **首頁 7 張卡片同樣權重平鋪**，回答不了「現在該做什麼」。新球團一進來多半是「不能做」的資訊：0 勝 0 敗 ---、資金 0、「目前資源還不夠升級」、紅字「資金不足」、灰掉的領取按鈕。
2. **直播與「自動比賽」重複又太技術**：「剩餘 5:00」與「下一場完成 5:00」同時出現；「可結算」「更新進度」是系統內部的概念（結算本來就會自動做）。電腦版目前比賽只佔半欄，旁邊空白。
3. **收益 → 養成的循環沒有說明**：不知道收益要手動領取、經驗是升級用的；升級入口在 陣容 → 球員 → 養成 三層深，首頁按鈕不說還差多少。
4. **升級回饋弱**：能力表只到小數一位（常常看起來沒變），升級後只有一行 toast，不知道何時生效。
5. **聯盟目標看不出差距**：只寫「最近 60 場勝率達到 60%」，沒有目前多少、還差多少；陣容何時生效只在陣容頁說明。

## 2. 首頁的層級

由上到下：

1. **目前比賽**（直播入口）：對手、比分、局數、出局、壘上、剩餘時間、觀看比賽。底下一行說明「每 5 分鐘自動打完一場，離開也會繼續（最多 8 小時）」與已完成場數；比賽打完、結算中時顯示一行狀態。原本的「自動比賽」卡片（倒數、可結算、更新進度）拿掉：倒數跟直播的剩餘時間重複，結算本來就由放置流程自動處理。
2. **目前建議**：只有一個（見第 3 節）。
3. **新手任務**：未完成時才佔空間（見第 4 節）。
4. **球隊**：戰績、可用資源、戰力，養成與招募入口；資源不夠升級時說明「升級還差 N 經驗、M 資金」。
5. **聯盟**：晉級進度（見第 6 節）。
6. **未領取收益**：沒有收益時降成一行說明與停用的按鈕。
7. **最近比賽**。

視覺權重：只有「目前比賽」與「目前建議（有事可做時）」用粗框、深陰影與黃色主按鈕；其他區塊用細框、淺陰影。電腦版維持兩欄，但目前比賽、目前建議、新手任務、收益、最近比賽橫跨整列，只有「球隊」與「聯盟」並排。

## 3. 目前建議（`application/guidance.ts`）

純函式 `suggestNextAction(club, { canWrite })`，第一個成立的規則就是建議：

| 優先 | 條件 | 建議 | 按鈕做什麼 |
|---|---|---|---|
| 1 | 有未領取的資金或經驗 | 領取比賽收益 | 直接領取（不花資源、冪等，跟收益卡片的按鈕同一個入口） |
| 2 | `eligibility().ok` | 挑戰下一聯盟 | 捲到聯盟卡片、焦點放在「挑戰下一聯盟」；**不替玩家挑戰** |
| 3 | 現有資產付得起某位上場球員的下一級 | 培養某位球員 | 打開那位球員的養成畫面；**升級仍要玩家按** |
| 4 | 招募來、在預備名單、比上場同類型最弱的人強 | 讓某位球員上場 | 前往陣容 |
| 5 | 以上都沒有 | 觀看目前比賽，附上「下一個目標：某某升級還差多少」 | 觀看比賽（較輕的連結，主按鈕就在正上方） |

- **為什麼領取排第一**：領了才能花；而且它不消耗任何東西。
- **為什麼挑戰排在培養前面**：晉級資格是稀有、而且會因為之後輸球而消失的機會；培養隨時都能做。
- 培養的對象：先發打者與先發投手優先（「主力」），同組等級低的優先（最便宜），同級看能力高的。
- **不顯示做不到的事**：1～4 都要寫入存檔，唯讀分頁（沒有 Web Locks、別的分頁可寫）一律只剩 5；資源差 1 點也不建議升級。
- 規則是純函式、不讀時間，測試直接餵存檔。

## 4. 新手任務：推導還是存狀態

| 任務 | 判斷 | 來源 |
|---|---|---|
| 建立自己的球隊 | 有球團就完成 | — |
| 觀看一場比賽 | 成功進入直播（不要求看完） | **新增** `onboarding.watchedLive` |
| 完成第一場比賽 | 勝 + 敗 ≥ 1 | 推導 |
| 領取比賽收益 | 領到「不是 0」的收益 | **新增** `onboarding.claimedRewards` |
| 培養一名球員 | 花過經驗（只有升級花經驗） | 推導 |
| 調整自己的陣容 | 儲存過一次配置真的不同的陣容 | **新增** `onboarding.lineupChanged` |

比較過的做法：

- **全部推導**：「看過直播」「改過陣容」在存檔裡完全沒有紀錄，做不到。
- **領取用推導**：`assets > 0` 不行（題目指出的初始資源、花掉之後又變 0）；`nextClaimSeq > 0` 也不行，服務層允許領取 0（測試實際抓到這個情況）。所以改成在領取的同一次存檔記旗標。
- **另開一個 localStorage key 存旗標**：不用改存檔格式，但任務跟球團脫鉤（重設球團不會重設任務）、沒有 revision 保護、多一套讀寫。
- **採用**：推導得出的就推導；推導不出的三個旗標 + 收合狀態放進球團存檔（schemaVersion 8，約 80 bytes）。

寫入方式（全部在 ClubLock 內讀最新存檔、用 revision 存檔）：

- `lineupChanged`、`claimedRewards`：在 `updateSettings`、`claim` **原本那一次存檔**裡一起記，不多寫一次。原樣再存一次陣容、只改戰術、領到 0 都不算。
- `watchedLive`：進入直播成功後呼叫 `markWatchedLive`；已經是 true 就不寫入。所以每個球團最多因為觀戰寫入一次，打開首頁、重繪、重複觀戰都不寫入。唯讀分頁不記（下次在可寫分頁觀戰再記）。
- `collapsed`：玩家按「收起／展開」才寫入，值沒變不寫入。
- 旗標只會從 false 變 true（收合除外），所以不同分頁的寫入不會讓任務「變回未完成」；寫入走 revision 檢查，舊的畫面不會覆蓋較新的球團資料。
- `onboarding` 不是比賽計畫的輸入，寫入它不需要結算、也不需要固定進行中比賽的計畫；測試確認「觀戰＋收合」與「完全不碰」的同一個球團，兩小時後結算出的比賽、經濟、聯盟一模一樣。

呈現：

- 不限順序、完成自動打勾、整塊可以收起（只剩一行「新手任務 3/6」與進度條，可以再展開）。
- 未完成的任務有一句說明；能做的放一個小按鈕（觀看比賽、領取收益、前往陣容）。**跟目前建議是同一件事時，任務不放按鈕，改成「見上方建議」**，避免兩個地方叫玩家做同一件事。
- 「領取收益」還沒有收益時說明「第一場打完就有收益可以領」；「培養球員」資源不夠時說明最便宜的升級還差多少。
- 「調整陣容」一定做得到：初始 14 人都在陣容裡、沒有預備球員，但交換兩位先發的棒次就是合法的變更；說明文字直接寫出這個做法。
- 全部完成後只剩一行「新手任務全部完成！接下來的長期目標是晉級聯盟」，收起後就不再出現。
- 不阻擋任何功能，不需要完成任務才能挑戰聯盟；不覆蓋直播。

## 5. 升級預覽與回饋

- 養成畫面最上面加「升級預覽」：`Lv.N → Lv.N+1`、會提升的每項能力（兩位小數，`升級前 → 升級後`、`+變化量`）、整體能力。數字全部是 `progression.ts` 的 `leveled()` 算出來的；沒有提升的能力不列（已達上限時，能力表的「下一級」欄顯示「上限」而不是 ±0）。
- 升級成功後在畫面上留一段回饋：升到幾級、各項提升多少，並說明「**新能力將從下一場尚未開始的比賽生效。**（第 N 場起；進行中的比賽維持開賽時的能力）」。N 來自升級後的存檔：升級時已經用升級前的狀態固定進行中那一場（Phase 5B 的 `liveMatch`），所以 N = `idle.nextMatchIndex + 2`（從 1 數）。

## 6. 聯盟目標

全部取自 `eligibility()`，不另外寫條件：

- `已完成 18 / 100 場（還差 82 場）`；達成後 `已完成 168 場（需要 100 場）`。
- `最近 60 場勝率 53%・需要至少 60%（還差 7%）`；還不滿 60 場時 `最近 18 場勝率 61%・需要打滿 60 場、勝率 60%`。
- 冷卻：`上次挑戰失敗：再完成 5 場才能再挑戰`。
- 未達成：說明晉級後收益倍率，並說明「這是長期目標」；達成：卡片變成強調色、「晉級條件都達成了！」與挑戰按鈕。

## 7. schemaVersion 8 遷移

- V7 → V8 只加 `onboarding`，其他欄位一個字都不動；串在既有的 3 → 4 → 5 → 6 → 7 之後，原始文字備份到 `backup-schema7`（沿用既有的不覆寫規則）。`legacyV7.ts` 凍結 V7 型別。
- 舊存檔沒有紀錄的不猜：`watchedLive`、`lineupChanged` 一律 false。
- `claimedRewards` 從帳務推導：到 V7 為止沒有任何直接進資產的收入，`earned − unclaimed`（= 歷來領取總額）> 0 就是領過。
- 已經打過比賽的球團 `collapsed = true`：老玩家的首頁只多一行可展開的進度，不會被新手任務佔住。
- fixture `club-v7-phase5b.json` 是 Phase 5B 程式實際產生的存檔（168 場、多次領取、升級、招募、交換棒次）。

## 8. 不做的事

沒有每日登入、簽到、每日任務、額外貨幣、成就、排行榜、PVP、賽季、新稀有度、新聯盟、雲端存檔、即時戰術介入、大型動畫改版。比賽規則、`MatchRunner`、`AutoCoach`、`LiveMatch`、`LivePlayer`、`LeagueService`、`IdleEngine`、`EconomyService` 的行為都沒變；`npm run balance:v2` 的輸出跟修改前逐字相同。

## 9. 之後（Phase 6B 建議）

- 戰術頁也套用同樣的「改了什麼 → 從第幾場生效」回饋，並在戰報標示每場用的戰術。
- 「目前建議」加上「戰術」與「招募」的規則（例如預備名單空著、資金足夠時建議招募），先觀察玩家實際的操作紀錄再決定門檻。
- 第一次挑戰聯盟前的短說明（挑戰賽是一場定勝負、失敗要再打 12 場）。
- 歡迎回來摘要加上「這段時間的建議」（例如累積了多少可以升級）。
