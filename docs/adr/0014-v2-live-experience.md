# V2 直播觀戰體驗：精彩時刻、結果揭露時間、關鍵打席與局間轉場

Phase 6B 只改善「觀看進行中的比賽」的感受，不改比賽模擬、結果、獎勵、聯盟數據與存檔格式。

## 1. 原本的問題

- **結果被提早劇透**：5B 已經讓比分條等狀態在排定時間才提交，但同一格裡的「事件演出」沒有分段。投球結果文字在投球動畫開始時就寫出來，擊球軌跡、全壘打大字、得分大字、紀錄文字都在這一格的提交時間之前就出現。比分條沒變，球場上已經寫著「全壘打！」。
- **只有一般事件的演出**：有全壘打、三振、雙殺、得分、失誤的大字，但沒有追平、超前、逆轉、再見、滿貫的概念。對手全壘打和我方全壘打用同樣的歡呼。
- **沒有緊張感**：九局下滿壘兩出局，看起來跟一局上無人出局一樣。
- **局間沒有節奏**：半局結束、換投只在紀錄裡多一行字；比賽結束直接跳勝負面板。

## 2. 現有架構分析

| 問題 | 結論 |
|---|---|
| GameEvent | `pitch`、`play`（16 種結果，含跑者移動、得分、擊球距離、雙殺記號）、`steal`、`substitution`、`halfInningEnd`、`gameOver` |
| 已有動畫 | 投球（球種軌跡＋投球視角）、擊球飛行、跑壘、盜壘、佈陣；大字：全壘打（含數據卡）、三振、雙殺、得分、失誤 |
| 只有文字 | 換投、代打、半局結束、比賽結束 |
| 資料夠不夠 | `ReplayFrame` 有事件、這一格之後的狀態；前一格的 `after` 就是這一格之前的狀態。追平、逆轉、再見、滿貫都能從資料判定；關鍵打席只需要之前的狀態 |
| 動畫會不會超時 | 每一段動畫都用時間預算縮放（最多放慢 1.3 倍、不會超過預算）；大字的顯示時間也有上限 |
| 不破壞 V1 | 只用 V1 既有的 `FieldRenderer`、`PitchCam`、`BURST_SVG`、音效；V1 的程式（`src/sim`、`src/ui`）沒有改動 |
| 手機效能 | 不做全螢幕重繪、不做持續的粒子系統；彩帶最多 18 個 span、1.3 秒後移除；閃光是一層 CSS 動畫 |

## 3. 精彩時刻分類（`application/matchMoments.ts`，純函式）

| 分類 | 判定條件 |
|---|---|
| `score` | 打擊方這一格得分 > 0（用比分差，盜回本壘、暴投等也算） |
| `tieGame` | 得分前打擊方落後，得分後同分 |
| `takeLead` | 得分前打擊方沒有領先，得分後領先；得分前是落後的話 `comeback = true`（逆轉） |
| `homeRun` | 這一格有全壘打（打者、帶回幾分；距離只有事件有提供時才有） |
| `grandSlam` | 全壘打帶回 4 分 |
| `walkOff` | 這一格有 `gameOver`、是下半局、主隊打擊、得分前主隊沒有領先、這一格有得分、贏家是主隊。不能只看「九局下得分」 |
| `clutchSituation` | **只看事件發生前的狀態**：7 局以後、得點圈有人、打擊方落後 0～（壘上人數 + 1）分（這個打席有機會追平或超前）。9 局以後兩出局、或 9 局下以後主隊可能再見是最高等級 |

另外也判定三振（揮空或站著不動，看最後一球）、雙殺（出局的跑者來自模擬的跑壘結果，不猜）、這一格是否結束半局或比賽。

**優先序**：`walkOff > grandSlam > homeRun > takeLead > tieGame > score`。同一格只演一個主要演出，其他資訊放在同一個大字的小字裡。例如九局下落後三分、滿壘的再見滿貫全壘打，只演一個「再見滿貫全壘打！」，小字是「4 分打點・最終 5 : 4」。

我方與對手用一樣的分類，`ours` 決定語氣：我方是振奮的演出；對手只用客觀的播報（灰色大字「對手全壘打」、灰色橫幅「對手逆轉」），沒有彩帶、沒有歡呼。

## 4. 結果揭露與 LiveSchedule 的時間契約

5B 的契約不變：第 i 格在 `endOf(i)` 正式提交，最後一格在 `endsAt` 提交。Phase 6B 把每一格的演出拆成兩段：

- **懸念（prelude）**：關鍵打席提示、換投公告、打者上場、盜壘起跑、投球飛向本壘。只用這一格之前的狀態，不揭露結果。投手先準備，球剛好在 `endOf(i)` 到達本壘。
- **揭曉（reveal）**：投球結果文字與音效、擊球軌跡、跑壘、比分條、大字、精彩時刻、局間轉場。**一律在這一格提交之後**。

所以第 i 個時間段 `[startOf(i), endOf(i))` 先演「第 i − 1 格的揭曉」，再演「第 i 格的懸念」。時間段長度依兩段的權重分配（`preludeWeight`、`revealWeight`，跟原本的 `frameWeight` 同比例），整場仍然是 5 分鐘。首頁「目前比賽」卡片與直播用同一個排程，比分一致。

各種結果的揭露時間：

| 內容 | 最早什麼時候出現 |
|---|---|
| 好球／壞球文字、球數燈、投球視角的進壘點、界外球的後續軌跡 | 那一球的提交時間 |
| 擊球軌跡、跑壘、得分大字、全壘打大字與距離、追平／超前／逆轉橫幅 | 那一格的提交時間（軌跡從提交時開始；比分條等球落地、跑者到壘才換） |
| 三振 K、雙殺 | 那一格的提交時間 |
| 再見、比賽結束、最終比分 | `endsAt`（最後一格在 `endsAt` 提交，揭曉接在後面） |
| 勝負面板 | `endsAt` 之後、最後一格的揭曉演完 |
| 關鍵打席、換投公告 | 懸念段（提交前）：只用已經發生的狀態，或投球前就確定的事 |

**投球動畫的前段與結果（PR #11 review）**：球場替身介面把投球拆成兩個方法。
- `pitch(ms, 球種, 投手)` 是中性前段，**沒有結果參數**。球場的球飛到本壘就停住，不消失也不飛出去；投球視角朝好球帶中心飛到軌跡的 80%（`APPROACH`），還沒到進壘點。
- `pitchResult(result, ms)` 在提交後才播：投球視角從中性軌跡平順轉到真正的進壘點（壞球在好球帶外），界外球畫出後續軌跡，打進場內時球留在本壘，其他結果把球收起。
- 這兩組方法是 `FieldRenderer.pitchTravel()` / `pitchOutcome()` 與 `PitchCam.approach()` / `finish()`，只給 V2 直播用。V1 的 `pitch()` / `play()` 一行都沒改。

其他規則：

- **超出預算**：揭曉段超出預算時，同一個時間段剩下的時間如果少於 `MIN_PRELUDE_MS`（40 ms），就跳過懸念段（下一球的投球前段），直接等提交，不讓動畫把比賽往後拖。落後超過一格時照舊直接同步。所以延遲最多就是那一段超出的時間，不會累積。
- **時間預算**：揭曉段的預算是 `revealShare × 時間段長度`；懸念段用到 `endOf(i)` 為止的剩餘時間。動畫依預算縮放；大字顯示時間在 0.5～4.2 秒之間（依種類）。最後一格的揭曉最多 `FINAL_REVEAL_MS`（4.5 秒）加 0.6～2.6 秒的停留，接著顯示勝負。
- **比分條**：提交時先把狀態交給畫面，畫面等揭曉動畫走到結果才顯示（只會比提交晚，不會比提交早）。中途暫停或中斷時直接顯示已提交的狀態。
- **落後**：畫面落後超過一格（背景分頁、系統負載、時間跳動）時直接同步到當下，不補演錯過的揭曉。
- **暫停、繼續**：暫停只停自己的畫面；繼續時重新同步，不重演暫停前的特效、不重播音效。
- **再見只演一次**：再見的大字、彩帶、勝利音效都在最後一格的揭曉；勝負面板接在後面，不再重複勝利動畫。

## 6. 動畫技術與效能

- **技術**：只用 CSS animation（爆炸框彈出、閃光、彩帶、橫幅、轉場、聚焦框脈動）、既有的 Canvas 球場與 Web Audio 合成音效，沒有新增任何套件。觀戰畫面仍是動態載入的獨立 chunk（14.2 KB → 22.7 KB，gzip 8.7 KB）。
- **降低動態效果**：系統設定 `prefers-reduced-motion` 時不閃光、不撒彩帶、不脈動、大字不彈跳；大字、橫幅、轉場的文字照樣顯示。
- **清理**：所有特效計時器都經過同一個 `later()`，關閉時全部清掉。彩帶播完就移除 DOM。音效以「格＋種類」去重。背景分頁、ResizeObserver 沿用 5B 的處理。
- **實測**：在 Chrome 快速開關 10 次之後，沒有留下 overlay、interval，2 秒內 `requestAnimationFrame` 呼叫 0 次。
- **判定成本**：精彩時刻判定＋關鍵打席每格約 1.5 µs，一場約 0.4 ms。

## 7. 已知限制

- 換投公告在懸念段（投球前）出現。它不是比賽結果，是投球前就確定的事，跟電視轉播一樣先公告。
- 擊球軌跡從提交時開始，比分條等球落地才更新。長距離全壘打的大字大約在提交後 2～3 秒出現。
- 最後一格的揭曉在 `endsAt` 之後演出（最多約 7 秒）。這段期間按鈕仍是「暫停畫面」，演完才變成「比賽結束」。
- 晉級挑戰賽的觀看沿用同一套演出。它沒有真實時間，所以依序演完整一格，並保留暫停、調速度、直接看結果。
- 模擬引擎沒有「暴投」「捕逸」這類事件，所以沒有對應演出；得分仍由比分差判定，不會漏算。
