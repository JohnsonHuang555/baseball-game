# V2 招募市場：三選一、確認簽約才扣款、價格 2,000＋400

## 背景

原本的招募是「付 4,000＋800×n 資金 → 隨機得到一位打者或投手」。玩家沒有選擇權，也看不到新球員跟目前陣容比起來怎樣，招募像是花錢抽獎。

目標：保留隨機發掘球員的樂趣，但讓玩家有選擇權，而且只有確定簽約才花錢。

**不做的事**：稀有度、十連抽、保底、付費刷新、每日免費抽、新貨幣、交易、合成、碎片、裝備、真實金錢。

## 決定

### 1. 流程

1. 選打者或投手。
2. 看三位候選人：總評、能力、流派與特性，以及跟目前陣容的比較。
3. 選一位。
4. 按「確認簽約：X 資金」。

只有第 4 步會扣款。新球員 Lv.1，放進預備名單，不自動上場（保留手動換陣容）。

### 2. 候選名單是純函式推導，不存檔

```ts
recruitCandidates(club, role): Player[]   // 3 人
```

**種子的推導**：

- **基礎種子**：`deriveSeed(clubSeed, recruitment.count, SEED_SALT.recruit) ^ 角色鹽`，跟舊版單一招募的種子相同。
- **每個候選位置**：再用 `deriveSeed(基礎, candidateIndex, SEED_SALT.recruitCandidate)` 推出各自的亂數。

**確定性**：

- **不會換人的情況**：同樣的球團種子、招募次數、角色，永遠是同樣三個人。關閉視窗、重開、重新整理、切換角色或分頁都不會換人。
- **函式沒有副作用**：不改球團、不扣資金、不加招募次數、不動 revision，也不觸發固定比賽計畫或結算。

**產生方式與編號**：

- **能力分布**：沿用 `generateBatter`／`generatePitcher` 與 `RECRUIT_CONFIG.mean`。
- **編號**：`r<招募次數>-<產生器編號>`。招募次數只增不減，所以不會跟歷史上任何球員撞號。
- **撞號的處理**：跟既有球員或前面的候選人撞號時，由同一條亂數再產生一次，仍然是確定性的。

### 3. 簽約：只傳角色與候選位置，服務層重建

```ts
recruit(deps, { opSeq, role, candidateIndex, expectedCount })
```

在 ClubLock 裡依序處理：

1. **讀最新存檔，用舊名單結算到期的比賽。**
2. **檢查請求格式**：角色、候選位置 0～2、招募次數。
3. **判斷是不是重送**：同一個序號，而且 `requestKey = recruit:<角色>:<招募次數>:<候選位置>` 跟最近一筆相同，就回傳原本的結果。
4. **檢查名單有沒有過期**：`expectedCount` 跟存檔的招募次數不同，就丟 `stale-candidates`，畫面重新載入並提示重新選擇。
5. **檢查資金與名單**：資金不足丟 `insufficient`，名單已滿丟 `roster-full`。
6. **用最新存檔重建候選名單，取出那一位。**
7. **固定進行中的比賽**（沿用 `freezeLiveMatch`），再扣款、加入預備名單、招募次數 +1，最後**一次存檔**。

**安全性**：

- **不信任畫面**：畫面不傳球員資料，所以竄改畫面或用舊名單都簽不到別人。
- **存檔失敗**：什麼都不變，沒有部分簽約；重試會簽到同一位。
- **不同候選人**：`requestKey` 不同，不會被誤判成同一筆重送。

**多分頁**：

- **A 分頁先簽約**：B 分頁拿最新的序號、但畫面上是舊的招募次數去簽約，會被 `stale-candidates` 拒絕。
- **兩個分頁同時簽約**：ClubLock 讓它們依序執行，後到的那個序號已經被用掉，會被 `stale-request` 拒絕。
- **沒有 Web Locks 時**：靠 revision 檢查讓其中一個失敗。

**畫面**：

- **過期提示**：畫面收到別的分頁寫入時，發現招募次數變了，會換成新的一批候選人、清掉選擇並提示。
- **重複送出**：連點由 ClubController 的 single flight 擋住。

### 4. 跟目前陣容的比較（`recruitCompare.ts`）

- **打者**：跟**守本職位置的先發**比，雙方都用守那個位置的實際守備（`fieldingAtPosition`），所以不會只看總評而忽略守位。陣容裡沒有人守那個位置時，改跟指定打擊比打擊三項。
- **投手**：比先發強，就跟先發投手比；不然跟最弱的後援比。
- **結果標示**：只描述**能力數值的預估差距**，不承諾勝率。
  - 判定：綜合能力差距 ≥ 0.3 是「能力較高」、≤ −0.3 是「能力較低」，其他是「能力相近」。
  - 項目：單項差 1 以上列為「能力較高的項目」或「能力較低的項目」。
  - 卡片上方註明：這是能力數值的預估差距（候選人 Lv.1，對方是目前養成後的能力），不代表一定會贏更多比賽；羈絆、特性、左右打與對手都會影響結果。
  - 畫面不使用「補強」「變強」這類暗示比賽結果的字眼。
- **不替玩家決定**：畫面不幫玩家選；只有平衡模擬用 `bestCandidateIndex`（差距最大者）代表「會挑的玩家」。

### 5. 價格

`RECRUIT_CONFIG.baseFunds = 2000`、`stepFunds = 400`，公式不變：`base + count × step`。第一次 2,000，第二次 2,400，第三次 2,800，之後每次 +400。不花經驗；UI 不另寫公式。

## 既有存檔相容（不需要遷移）

| 項目 | 處理 |
|---|---|
| `recruitment.count` | 不清除，繼續累計；下一次的價格用新公式。例如已招募 3 次的球團，下一次是 3,200 |
| 已招募的球員 | 不重新產生、不改能力；舊的 `r<n>-` 編號不會被新候選人用到 |
| 支出紀錄 | 舊的 `requestKey: 'recruit:batter'` 與 `recruitIndex` 原樣保留。新紀錄多一個選用欄位 `candidateIndex`（0～2，存檔驗證會檢查），舊紀錄沒有這個欄位也合法 |
| 退款、補扣 | 都沒有：歷史支出不重算 |
| 歷史比賽、已固定的 LiveMatch | 不受影響。簽約前先固定進行中那一場，新球員從下一場才可能上場 |
| schemaVersion | 仍是 8 |

**舊版的重送**：例如舊分頁還開著，送出舊格式的請求。舊格式的請求沒有 `candidateIndex`／`expectedCount`，會被當成格式錯誤拒絕。舊版剛完成的那一筆，就算序號對上，`requestKey` 也不同，會被 `stale-request` 拒絕，所以不會重複簽約。

## 平衡評估

**資料規模**：30 個種子 × 每天 1／2／6 次 × 策略 D（積極招募，名單滿了就釋出最差的預備球員再招募）與 E（照首頁建議，最多 20 人）× 三種方案，共 540 次 30 天模擬。

**三種方案**：
- **A 舊制**：4,000 起，每次 +800，隨機一位。
- **B 新制**：2,000 起，每次 +400，三選一。
- **C 折衷**：3,000 起，每次 +500，三選一。

**三選一的策略**：挑能力比比較對象高最多的那位（`bestCandidateIndex`）。

**資料與報告**：
- **原始資料**：`docs/balance/data/recruit{Old,New,Mid}.jsonl.gz`。
- **完整表格**：`docs/balance/data/recruit-market-compare.md`。
- **重現方式**：見 `docs/balance/recruit-market-report.md`。

**主要結果**（E 是一般玩家的代表）：

| | A 舊制 | B 新制 | C 折衷 |
|---|---|---|---|
| E 每天 1 次：第一次招募（P50 天） | 6.0 | 3.0 | 5.0 |
| E：簽下的球員平均總評 | 4.95 | 5.61 | 5.62～5.64 |
| E：簽下的人能力高於比較對象（預估差距 ≥ 0.3） | 21～22% | 53～54% | 51～52% |
| E 每天 1 次：30 天到傳奇 | 50%（P50 30 天） | 63%（21 天） | 60%（25 天） |
| E 每天 6 次：到傳奇 P50 | 8.3 天 | 5.2 天 | 6.2 天 |
| E：傳奇聯盟一般比賽勝率 | 47～51% | 53～55% | 53～55% |
| E：挑戰賽失敗率 | 53～55% | 54～56% | 56% |
| D 每天 1 次：30 天到傳奇 | 70%（main 實測 47%） | 87% | 93% |
| D 每天 6 次：到傳奇 P50／P90 | 6.3／17.3 天 | 3.8／6.0 天 | 3.8／9.5 天 |
| D：傳奇聯盟一般比賽勝率 | 52～53% | 59～62% | 58～61% |

**觀察**：

1. **提升主要來自「三選一」，不是降價。**
   - 簽下的球員平均總評從 4.95 變成 5.6，能力高於比較對象的比例從約 2 成變成 5 成。B 和 C 幾乎一樣。
   - C 的價格高 50%，E 的結果卻只比 B 差一點，例如每天 1 次到傳奇 60% 比 63%。
   - 所以調回較高的價格，擋不住三選一帶來的強化。
2. **一般玩家（E）**：
   - **變強幅度溫和**：戰力多約 0.1～0.2。
   - **進度**：每天 1 次到傳奇從 50% 變成 63%。
   - **難度仍在**：傳奇勝率仍在五成左右，挑戰失敗率不變，沒有變成「一直贏」。
   - **資金**：招募變便宜，第 30 天的資金餘額變多，但經驗仍然是瓶頸（餘額只有數百）。
3. **積極招募的玩家（D）明顯變強**：見下面的「已知的設計取捨」。
4. **舊制基準的說明**：
   - **舊制模擬用的是新的候選產生器**，只取第 0 位，代表「隨機一位」。
   - **E 跟 main 實測一致**：每天 1 次到傳奇 50% 比 47%。
   - **D 的波動大**：D 在 main 實測是 47%，模擬是 70%，兩邊的球隊戰力幾乎一樣（6.09 比 6.14）。差距來自 D 反覆招募造成的變異，所以 D 的「到傳奇比例」要看趨勢，不要看單一數字。

### 已知的設計取捨：積極招募的玩家（策略 D）

**這不是「平衡完全沒有問題」**：新制讓反覆「釋出 → 再簽」的玩家明顯變強，這是採用 B 的已知代價。

**數據**（30 個種子；A 舊制 → B 新制）：

| 策略 D | A 舊制 | B 新制 |
|---|---|---|
| 每天 6 次：到傳奇 P50／P90 | **6.3／17.3 天** | **3.8／6.0 天** |
| 傳奇聯盟一般比賽勝率（每天 1／2／6 次） | 51.6%／52.9%／52.2% | **58.6%／61.4%／62.2%** |
| 30 天簽約次數（每天 1／2／6 次） | 16.4／20.8／16.8 | 35.3／44.1／38.2 |
| 30 天釋出次數（每天 1／2／6 次） | 0.9／4.8／1.0 | 19.3／28.1／22.2 |
| 30 天招募花費（每天 1／2／6 次） | 167,547／248,933／173,387 | 313,947／469,453／360,920 |
| 30 天累計支出：招募＋升級（每天 1／2／6 次） | 398,135／805,680／1,207,799 | 442,236／884,941／1,344,507 |
| 招募佔資金收入（每天 1／2／6 次） | 42%／31%／14% | 71%／53%／27% |

**怎麼看這些數字**：

- **原因**：價格減半，讓「名單滿了就釋出最差的預備球員、再簽一位」的循環便宜很多。30 天的簽約次數翻倍，釋出次數從約 1～5 次變成 19～28 次，每次又都從三人裡挑最好的。
- **結果**：
  - **傳奇勝率**：約 59～62%，比一般玩家（53～55%）高。
  - **到頂速度**：高頻玩家第 4 天左右就到傳奇聯盟。
- **代價**：招募花費佔資金收入的 27～71%，升級的資金相對變少。經驗仍然是瓶頸，第 30 天的平均等級沒有比較高。
- **模擬跟正式遊戲一致**：
  - **用的是正式服務**：「釋出 → 招募」用的是遊戲本身的 `release`／`recruit` 服務，價格是 `recruitCost(第幾次)`（招募次數只增不減，釋出不會讓價格變回便宜）。
  - **釋出不花錢、不退款**：跟遊戲一樣。
  - **有測試驗證**：`scripts/balance/simulate.test.ts` 確認每次簽約的價格跟公式一致，模擬記的招募花費、快照裡的累計、遊戲的支出紀錄三者對得上。
  - **不一樣的地方**：模擬沒有算「操作要花的時間」。實際玩家每次釋出都要在養成畫面二次確認，簽約也要看完三張卡片。
- **C 折衷壓不下來**：傳奇勝率 58～61%，跟 B 差不多。價格不是主要的槓桿，提升主要來自三選一。

**這次不處理的理由**：

- **玩家群小**：會這樣反覆操作的是很投入的高頻玩家。
- **一般玩家仍在原本的範圍**：E 的勝率、挑戰難度都沒有超出原本的範圍。
- **任務範圍**：這次的任務明確要求不加稀有度、付費刷新、冷卻時間或限制招募的機制。

**之後如果要調整**：先看實際玩家資料。只調數值的最小選項是提高 `stepFunds`，讓反覆簽約變貴得更快；需要新規則的做法（例如限制釋出後再招募）不在這次範圍。

**結論**：採用 B（指定方案），並接受上面記錄的設計取捨。

- **一般玩家（E）**：變強幅度溫和。傳奇勝率約 53～55%（原本 47～51%），挑戰失敗率不變，經驗仍然是瓶頸。
- **積極招募的玩家（D）**：明顯變強，每天 6 次到傳奇 P50 從 6.3 天縮短到 3.8 天，傳奇勝率約 59～62%。這是已知的取捨，不是平衡完全沒有問題。
- **C 不是有效的最小修正**：它對 D 幾乎沒有效果，對一般玩家只是讓第一次招募晚 2 天。

## 風險

- **積極招募的高頻玩家更快到傳奇**：策略 D 每天 6 次，P50 約 3.8 天、傳奇勝率約 59～62%（見「已知的設計取捨」）。到傳奇之後的長期目標，仍然是 ADR-0015 提到的後續課題。
- **比較標籤只代表能力數值**：卡片上的「能力較高／較低」是預估的數值差距，不保證換上場一定贏更多比賽，畫面上有註明。
- **候選人可以先看**：玩家可以先看三位再決定要不要招募，但不能「刷新」。換一批人只有一個方式：真的簽下一位，讓招募次數 +1。
