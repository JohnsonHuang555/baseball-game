# ADR 0018：V2 介面改版（設計稿 v7「放置經營」）

## 背景

Claude Design 的設計稿（畫布「骰子棒球 畫面設計」的「v7 放置經營」頁）重新整理了所有 V2 畫面：
外框、首頁、陣容、戰術、戰報、球員養成、招募市場、觀戰、對話框與系統狀態，並附元件表與動態說明。

## 決定

- 只改畫面，不改遊戲規則、存檔格式與服務層。所有數字仍來自原本的 domain／application。
- 外框：頁首放隊名、聯盟、總戰績與資金／經驗；手機底部導覽，1024 寬以上改成左側 96px 直立導覽。
- 首頁電腦版三欄（比賽與建議／球隊與收益／聯盟、任務、最近比賽）。DOM 順序就是閱讀順序，
  所以用 `matchMedia('(min-width: 1024px)')` 決定要不要分欄，跨過門檻時重畫一次。
- 新的共用元件：`icons.ts`（設計稿 IdIcon）、`dialog.ts`（標題列＋✕、可捲動內容、固定底部動作；
  手機的 sheet 從底部滑出；公告型對話框）、`draftBar.ts`（陣容、戰術共用的儲存列）。
- 按鈕改成元件表的四種：主要（黃，每個畫面最多一個）、次要（白）、危險（白底紅框）、停用（灰色虛線框）。
- Toast 分一般、成功、錯誤三種；停留 1.8 秒、淡出 0.4 秒、同時一則。
- 每個動畫都有「減少動態效果」的替代（直接顯示結果、不位移）。

## 跟設計稿不同的地方

- 聯盟卡沒有「挑戰冷卻：無」那一列；只有在冷卻中才顯示冷卻進度。
- 陣容的預備球員標籤用「預」，第二行補上本職守位（設計稿只有特性）。
- 簽約完成畫面保留上方的資訊列（球團人數、資金、下一次簽約價格）。
- 歡迎回來沒有「離開 N 小時，最多只累積 8 小時」那一行：回歸摘要目前沒有離開時間的資料。
- 單場戰報的打擊表是「打席」不是「打數」，投手表沒有「用球」：Box Score 沒有存這兩項。
- 晉級挑戰結果對話框新增次要按鈕「觀看挑戰過程」（有保留 Replay 時才出現）。

## 影響

- 測試的選擇器跟著新結構更新（例如儲存列改用 `data-action="save-draft"`、資訊格改看 `aria-label`）。
- 打包大小（gzip）：JS 76.2 → 86.9 KB、CSS 9.4 → 14.3 KB（頭像、圖示與新樣式）。

## 補充：對話框的焦點與鍵盤（review P2）

- `dialog.ts` 維護一個對話框堆疊。只有最上層處理鍵盤：
  - Tab／Shift+Tab 在對話框內循環。
  - 對話框裡有第二次確認（`role="alertdialog"`）時，焦點只在那個小框。
  - Escape 關閉最上層。
- 「最上層」也看畫面：之後又蓋了別的 `aria-modal`（例如從挑戰結果打開的觀戰），就讓那一層自己處理。
- 第一個對話框打開時把畫面快捷鍵換成空的，最後一個關閉時才還原。所以不論用什麼順序關閉，快捷鍵都不會錯亂。
- 關閉後焦點依序回到：原本的元素（還在畫面上時）、下一層對話框、目前的導覽分頁。
  - 先關掉下層時，上層會接手下層的開啟元素。
- 戰報依比賽時間分組（`playedAt`），不用結算時間。存檔升級前的比賽沒有 `playedAt`，用同一次結算的最後一場往前推估。

效能與版面驗收見 `docs/perf/v2-ui-v7-acceptance.md`。

## 補充：App 關閉時的對話框清理（review P1）

- **記錄開啟者**：每個對話框都記住是誰開的（`owner`，用該 App 的 ClubController）。
- **App.close() 的關閉流程**：呼叫 `closeDialogs(controller)`，從最上層往下，每一層都走跟按 ✕ 相同的正式流程：
  - 移除畫面、離開堆疊。
  - 還原快捷鍵、最後一層關閉時移除 keydown 監聽。
  - 呼叫 onClose（例如取消訂閱）。
- **只關自己的**：不再直接移除所有 `.v2-modal-overlay`，所以另一個 App 的對話框不受影響。
- **onClose 會收到原因**：`'user'` 或 `'dispose'`。
  - App 關閉（dispose）時只做清理：不揭曉挑戰結果、不 dismiss 歡迎或挑戰結果、不重畫、不搬動焦點。
  - 取消訂閱等清理照常執行。
