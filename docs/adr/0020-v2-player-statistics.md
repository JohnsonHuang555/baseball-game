# ADR 0020：V2 球員比賽數據與生涯紀錄（Phase 8）

- 狀態：已採用
- 相關：`docs/phase8-statistics-spec.md`（統計規格）、`docs/phase8-report.md`（效能、存檔大小與相容性驗證）

## 背景

玩家只能看到能力等級，無法判斷球員在正式比賽中實際表現如何。引擎原本的 `PlayerLine` 只有
`pa hits hr rbi so`／`outs runs k`，戰報用名字當 key、最近 50 場以外沒有任何個人紀錄。
目標：可信的 AVG／OBP／SLG／OPS／ERA／WHIP，近期與生涯，而且**不改變任何比賽結果**。

## 決定

### 1. 引擎：另外加一份正式記分，不改 PlayerLine

`src/sim/scoring.ts` 的 `Scorekeeper` 由 `Game` 在打席結束、盜壘、換人、半局結束、延長賽放跑者時呼叫：

- 只讀比賽狀態、**不呼叫亂數、不改事件流**；`PlayerLine` 原樣保留（錦標賽成長、MVP、潛力都不受影響）。
- 正確記錄 AB／BB／IBB／SF／SH／GIDP／ROE、1B～HR、R、投手 BF／Outs（含盜壘刺殺）／H／HR／BB／K。
- 自責分：跑者責任追蹤＋半局重建（失誤＝本來的出局）、後援不享有上場前的失誤機會（9.16(i)）、
  打席中途換投的保送歸屬（9.16(h)）、代打兩好球三振歸屬（9.15(b)）、延長賽二壘跑者非自責。
- 不需要新的規則版本；任何規則版本的舊 Replay 重播都會得到相同比賽與完整記分。

### 2. 存檔：獨立的 `ClubSave.stats`，而不是放在 `PlayerRecord`

| | 放在 PlayerRecord | 獨立 `stats.players`（採用） |
|---|---|---|
| 被釋出的球員 | 球員從名單移除，紀錄跟著消失 | 保留（`releasedAt`），戰報、詳情找得到 |
| 一致性 | 名單操作（招募、釋出、升級）都要顧及數據 | 只在結算時改，`throughMatch = nextMatchIndex` 一個不變量 |
| 存檔大小 | 相同 | 相同；已釋出的另有上限 |
| Migration | 每位球員都要補欄位 | 加一個欄位 |

- 每場 `SettledMatch.lines`：`[playerId, ...計數]`，固定欄位順序、結尾的 0 省略；有 lines 的新比賽不再重複存 Box Score 的名字陣列。
- 生涯 `stats.players[playerId]`：名字、角色、出場數、累計計數（完整長度陣列）、第一／最後一場、釋出時間。
- **防重複**：生涯與結算游標在同一次狀態轉換裡前進；`addMatchToCareer` 只接受 `matchIndex === throughMatch`；
  存檔驗證要求 `throughMatch === idle.nextMatchIndex`。重送、多分頁、中斷恢復都沿用既有的冪等結算。
- **已釋出球員**：保留最近 60 位，戰報（最近 50 場）裡還出現的永遠保留；更早釋出、戰報裡也找不到的才刪。

### 3. 期間

- 最近 10／30 場 = `recentMatches` 的最後 10／30 場（只有一般正式比賽，晉級挑戰不在裡面）；
  沒上場的比賽不增加 G，但仍佔視窗。
- 生涯 = `stats.players`。近期與生涯都轉成同一個 `Totals`，比率只由 `battingRates`／`pitchingRates` 從累積計數算。
- 比率分母 0 → `null` → 畫面「—」。樣本門檻：20 打席、30 出局（10 局），可在 `SAMPLE_CONFIG` 調整。

### 4. Migration V9 → V10

- `stats = { sinceMatch: nextMatchIndex, throughMatch: nextMatchIndex, players: {} }`，其他欄位一個字不動。
- 舊 Box Score 欄位不夠（沒有 AB、BB、2B、3B、被安打、ER），**不回填、不重新模擬**；
  畫面把生涯叫「記錄以來」並說明起點，舊戰報缺的欄位顯示「未記錄」。
- 原始文字逐字備份到 `backup-schema9`；寫入失敗時原本的存檔不變（沿用既有的遷移流程）。

### 5. 畫面

- 球員詳情：「比賽數據／球員能力」分頁；從養成入口預設能力（升級流程不變），從排行、戰報、招募進來預設比賽數據。
- 陣容頁多一個「球員數據」分頁（不加底部導覽）：打者／投手、期間、排序（ERA、WHIP 由低到高），
  比率排序時樣本不足另外列、不給名次；沒出場的放最後，數字「—」。
- 戰報：打擊 9 欄＋合計、投手 6 欄，名字欄固定、可左右捲動，名字可點（含已釋出）；舊比賽「未記錄」。
- 招募：能力比較不變；候選人固定「尚無本隊比賽數據」，只有被比較的現有球員顯示真實的最近 30 場。

## 後果

- 存檔約多 25 KB（50 場 lines ≈ 22 KB、生涯 ≈ 2～3 KB，已釋出紀錄上限約 10 KB）。
- 96 場離線結算的記帳約多 8 ms；模擬本身在量測誤差內。
- 之後新增任何會讓跑者上壘或得分的引擎事件（觸身球、暴投、野選、跑壘失誤），**必須同時更新 Scorekeeper**，
  否則 `scoring.test.ts` 的不變量（失分加總＝對手得分、出局數＝守備出局數）會失敗。
