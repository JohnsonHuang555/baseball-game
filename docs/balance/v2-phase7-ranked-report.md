# V2 Phase 7：競技積分／降級方案的平衡模擬

> 這份報告比較的數字**全部是模擬專用**（`scripts/balance/ranked.ts`），不是正式規則，也沒有寫進遊戲 Config 或存檔。結論與建議見 [RFC](../phase7-ranked-league-rfc.md)。
> **所有數字都是近似值、用來比較方案的相對差異，不能當成上線後的精確預測**（原因見最後的「近似與限制」）。

## 怎麼跑

```
npm run balance:v2:ranked            # 全部方案 × 每天 1／3／6 次 × B／E／D × 種子 1～3 × 45 天；預設 2 個行程平行，約 35 分鐘
npm run balance:v2:ranked -- --approx                    # 舊的整批近似（第一版報告用的方法），輸出 phase7-ranked-approx.json
npm run balance:v2:ranked -- --variants=C+3-2 --sessions=3 --strategies=E --seeds=1 --days=20 --jobs=1 --out=x.json
npm run balance:v2:ranked -- --report=docs/balance/data/phase7-ranked.json --compare=docs/balance/data/phase7-ranked-approx.json
```

- 比賽、獎勵、升級、招募、挑戰都由正式服務實際跑（同 Phase 6C 的 `simulate.ts`），積分只記在旁邊的影子狀態；降級時直接把模擬用的記憶體存檔改成下一級。
- **分段結算（這版的預設）**：正式設計是「降級那一場之後的比賽用新聯盟重新規劃」。模擬不改 Domain，改成把一次上線的離線結算切成好幾段，每段最多 `ceil(積分 ÷ 每場扣分)` 場（保護期內是剩下的保護場數、賽季方案是這一季剩下的場數），保證降級只會發生在一段的最後一場；下一段由正式的 `settleDue` 用新聯盟的對手強度與收益倍率規劃。跟正式結算的場次、種子、離線上限完全一樣（有測試比對沒有降級時兩種方式的結果相同）。
- 每格 n = 3 種策略（B 平均養成／E 跟著首頁建議／D 招募＋養成，代表弱／中／強球隊）× 3 個固定種子（1、2、3）；45 天；每天上線 1、3、6 次（平均分散）。
- 每天 1 次的有效結算只有 8 小時（96 場），3 次是每次 8 小時（96 場）、6 次是每次 4 小時（48 場）。

### 欄位

- **A→B P50**：第一次到 A 到第一次到 B 的天數中位數（只算兩者都到的球團）；括號是到了 A 的球團裡 45 天內到 B 的比例。
- **降級／千場**：該聯盟的降級次數 ÷ 在該聯盟打的一般比賽場數 × 1000。
- **一次上線就從安全區被降級**：那一次上線開始時積分還高於危險區（> 20），同一次上線的離線結算就降級的次數 ／ 降級總數。
- **危險區場數比例**：積分 ≤ 20 的場數比例。

## 解讀

1. **方案 A 的晉級變快很多**：+3／−2 的損益兩平勝率是 40%，現行是 60%。挑戰者→職業 P50 從 3.7 天（每天 3 次）變 1.0 天，每天 1 次從 11 天變 3 天；之後 56% 的球團被降級。
2. **A+2-2 是隨機漫步**：勝率五成的球隊在職業↔傳奇之間反覆升降，E 策略平均降級 6.7 次；一次上線就從安全區被降級 20／50（每天 3 次）。
3. **A+2-1 幾乎沒有降級**，但晉級跟 A+3-2 一樣快，積分沒有實際作用。
4. **C／D 的進度與基準完全相同**（晉級規則沒變）。45 天只有 B 策略的高頻玩家偶爾降級（11～22% 的球團，每千場 ≤ 0.07 次），危險區場數 ≤ 1%；E、D 沒有任何降級；每天 1 次的玩家完全沒有降級。
5. **保級緩衝（C+3-2r）效果很小**：觸發 6 次，降級次數 5 → 4，一次上線就被降級 2 → 1。降級本來就少，緩衝主要是心理上的安全感。
6. **B40（賽季）** 降級比 C 多（每天 6 次 67% 的球團），但因為一季 100 場才判定，不會「一次上線就掉」。
7. **D 的積分在挑戰者幾乎一直是滿的**：+3／−2 對勝率 45～60% 的球隊是正向漂移，挑戰者 92% 的場次積分 ≥ 80（職業 89%）。如果畫面上有「晉級區 80」，76% 的上線會看到「積分在晉級區、但 100 場／60% 還沒達成」——兩個條件互相矛盾（反過來「條件達成但積分不到 80」是 0%）。
8. **降級發生在一次上線的第幾場**：每天 1、3 次 P50 第 42～48 場（一批 96 場），6 次 P50 第 24 場（一批 48 場）。也就是整批近似模式下，平均每次降級後還有約 24～54 場被錯誤地用舊聯盟規劃。

## 分段結算與整批近似的差異（P2-2 評估）

第一版報告（`phase7-ranked-approx.json`）用整批近似：一次上線的離線比賽全部用上線當時的聯盟規劃，整批結算完才處理積分與降級。比較上表最後一節：

| 面向 | 整批近似的偏差 | 實際影響（這次的數據） |
|---|---|---|
| 降級後的對手強度 | 降級那一場之後、同一批的比賽仍用舊聯盟的對手（強 0.4），而且不計分 | 每次降級約 24～54 場；不計分讓降級後的積分恢復比實際慢 |
| 降級後的資源倍率 | 同上，這些比賽用舊聯盟的倍率（職業 ×1.45 vs 挑戰者 ×1.30），收入多算約 10% | 每次降級約多算數千資金，對 45 天的總收入可以忽略 |
| 升降級頻率 | A、C、B 的降級次數差 0～3 次；A+2-2 每天 3 次差最多（50 vs 47） | 結論不變 |
| 降級後重返原聯盟的時間 | A+2-2 每天 1 次 2.3 vs 4.0 天、B40 1.8～1.9 vs 2.0～2.2 天；其他差 ≤ 0.1 天 | 只有本來就頻繁升降的方案會偏差 |
| 離線結算批次大小 | 每天上線越少、一批越大（96 場），偏差越大；每天 6 次（48 場）偏差最小 | C 每天 1 次沒有任何降級，所以不受影響 |
| 一次上線就被降級 | A+2-2 每天 3 次 20 vs 15：整批近似低估了 | 高頻升降的方案的離線壓力比第一版報告的更高 |

結論：**第一版報告對方案 C 的結論不受影響**（C 的數字兩種方式幾乎相同，因為 C 的降級很少）；方案 A+2-2 在整批近似下低估了降級壓力。

## 建議值

見 RFC 第 5 節（方案 C 或 D，晉級不變；職業、傳奇保級積分 0～100、起始 50、勝 +3／敗 −2、歸零降一級、晉級後 20 場保護）。

## 近似與限制（以下的數字不能當成精確預測）

- **樣本小**：每格只有 9 次模擬（3 策略 × 3 種子）。降級是少見事件，比例的誤差很大（例如 C 的「有降級的球團 11～22%」只是 1～2 個球團）；重返天數也只有幾個樣本。
- **策略是腳本化的玩家**：不會因為降級或危險區而改變行為（例如加碼養成、換陣容），真實玩家大概會更快回去。
- **時間軸是理想化的**：每天上線時間固定、平均分散；真實玩家的上線間隔不規則，一次離線可能更長（但離線上限 8 小時一樣封頂）。
- **45 天**：每天 1 次的玩家只有 56% 到傳奇，傳奇聯盟長期（60～90 天）的保級壓力還要再跑。
- **影子狀態的邊界**：降級時模擬直接改記憶體存檔（把 highestTier／promotions 壓到同一級來通過現行驗證），挑戰時暫時補本聯盟戰績；正式實作的資料模型不同，這些只影響模擬本身，不影響比賽結果。
- **分段結算仍不是正式流程**：它重現了「降級後重新規劃」的效果，但正式實作還會牽涉進行中比賽（liveMatch）的固定計畫、跨分頁鎖與 revision，這些模擬都沒有涵蓋。
- **整批近似的舊資料**（`phase7-ranked-approx.json`）沒有 C+3-2r，也沒有記錄降級後仍用舊聯盟的比賽數；表中「每次降級約 24～54 場」是用分段結算的「降級發生在第幾場」與批次大小推算的。
