# Phase 9 PR 4：單場 MVP 的平衡

- 指令：`npm run balance:v2:mvp`（A 尺度校正、B 得獎分布、C 長期 30／60／90 天與正回饋）。這份報告用的參數：
  - `-- --games=1000 --seeds=3 --styles=balanced`（A、B 用 8,000 場；C 是均衡型，有／沒有特性訓練）
  - `-- --games=200 --seeds=2 --skipA --styles=power,speed,defense`（其他三種戰術的長期）
  - `-- --seeds=3 --skipA --styles=balanced --onlyTrain --noFeedback --perGrowth=25`、`--perGrowth=50`、`--maxUnits=3`（成長速度與上限的對照）
- 效能：`npm run bench:v2:mvp`。
- 「不同聯盟」那一節是加上這一節後用 `-- --games=1000 --skipA --skipLong` 跑的（其他節的數字不受影響）。
- 所有比賽都用固定種子，重跑結果相同；MVP 只看結算後的數據與事件，不影響比賽。

## A. 投手分數的尺度：用「一分的價值」校正，不是湊比例

RFC 的投手方向是「出局 × 聯盟每出局失分 − 自責分 × k」。關鍵是 k 要多大，才能跟打者的分數比較：

- **聯盟每出局自責分**：8,000 場量到 **0.1083**（每 9 局 2.92 分）。用這個值，平均水準的先發得 0 分。
- **打者的一分值多少評分**：每場我方打者評分加總，對我方得分做回歸：評分加總 = −1.66 + **1.47** × 得分（R² 0.76）。
  - RFC 的打者權重是 wOBA 式的尺度（一壘安打 0.9 vs 出局 −0.27，差 1.17），比「一分」大約 1.5 倍。
- **決定**：投手的「少失一分」也值 1.48 評分（`scale = 1480`）。打者多得一分與投手少失一分等值，投手不會因為公式尺度不同而吃虧或佔便宜。
- 三振不另外加分：三振已經反映在出局數與自責分裡，再加會重複計算。

**解讀：**
- **成長比 RFC 估計快很多**：RFC 估「+0.5 約需 500 場」，但一天 2 次上線就是約 192 場。先發投手約 1.5 天到上限，30 天時上場球員平均 +0.43（大部分人都到上限）。
- **沒有正回饋壟斷**：均衡型得獎最多的 1 人，有成長 18.5～19.7%、沒有成長 18.0～18.5%；前 3 人在後半段的占比，有沒有成長的變化差不多（C-3）。
  上限 +0.5 讓頂級球員不會越拿越多；這個結果不需要任何隱藏的輪替機制。
- **能力通膨**：有上限，所以是一次性的平移。90 天時上場平均能力 6.17 vs 6.05（+0.12，約等於打者 4 項能力中 1 項 +0.5）；相較之下 Lv.20 的主要能力成長是 +2.0，MVP 上限是它的四分之一。
- **四種戰術**：30～90 天的平均加成都是 +0.43～0.46、最快到上限 1.5～2 天，得獎最多 1 人的占比有沒有成長都差不到 1 個百分點，沒有哪種風格特別受益。
- **跟等級、特性訓練疊加**：MVP 加成在等級之後套用、上限 10；成長能力用 Lv.20 判斷空間，滿級後也不會被上限吃掉。跟特性訓練疊加時，加成與訓練各自生效（平均等級幾乎相同）。
- **會加速晉級**：3 個種子都到傳奇時，51.2 天 → 42.7 天（快 8.5 天、約 17%）；30、60 天的平均聯盟階級不變，差在最後一階（職業 → 傳奇）。
  - 放慢成長沒有用：每 25、50 次才成長，一個月內大家還是到上限（一天約 192 場），到傳奇 45.2、42.7 天。
  - 真正決定的是上限的大小：上限 +0.3 時是 48.0 天（快 3.2 天、約 6%）。

## 需要你決定：上限 +0.5 還是 +0.3

- 這次照規格建議用 **每 10 次 +0.1、上限 +0.5**，沒有改。
- 數據顯示它會讓「所有種子都到傳奇」的時間快約 17%（51.2 → 42.7 天；競技積分的 84 次長跑也是同一個方向，C-5），但沒有壟斷、沒有失控的通膨。
- 如果想保護晉級節奏，建議改成 **上限 +0.3**（只改 `MVP_CONFIG.maxUnits = 3` 一個常數，存檔格式與驗證都跟著上限走）：加速降到約 6%，球員仍有看得到的長期成長。
- 不建議用「放慢成長速度」處理：場數太多，速度幾乎不影響結果。

**切段到底花多少？** 拆開來量：
- **同一個球團、同樣的比賽**：關掉成長（1 段）vs 正式（41 段），中位數差 0.7%（上面那一行）。每段的固定成本（重新規劃、不再整份複製球團、跨段共用讓出計數）很小。
- **跟 main 比（`bench:v2:traits`，每個情境 15 次）**：
  - 關掉成長（比賽一模一樣）：7 個情境加總 1,255 ms vs main 1,240 ms（+1.2%，雜訊內）。選 MVP、收集事件、存檔驗證幾乎不花時間。

- 存檔：近期 50 場每場多一筆 MVP（約 40 bytes），全隊的 MVP 紀錄每人最多約 150 bytes；大約多 2～4 KB。
- 介面驗收（`scripts/ui-acceptance.py`，手機 4× CPU 降速）：長任務最長 261／320 ms（main 243／299 ms），首頁就緒 777 ms（main 832 ms），都在原本的範圍內。

## 已知限制

- **勝利打點**只作同分規則，不加分；取得領先的是失誤或雙殺時不記（沒有打點）。
- **觸身球**：引擎沒有這種結果，公式裡照樣有權重但永遠是 0。
- **聯盟每出局自責分**用一個固定值（平均對手 5.8 量測），不分聯盟；各聯盟的投手比例 23～28%，差異不大，所以沒有分聯盟設定。
- **跨角色同分**：打者優先是固定規則；8,000 場裡沒有發生過。
