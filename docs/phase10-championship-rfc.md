# Phase 10 PR 1：傳奇總冠軍賽（核心系統）RFC

狀態：實作中（PR 1）。慶祝動畫、外觀獎勵、賽季重置等留給 PR 2／PR 3。
平衡數據：`docs/balance/v2-phase10-championship.md`（`npm run balance:v2:championship`）。

## 1. 目標

傳奇聯盟是最高的聯盟，到了以後只剩「繼續變強、別降級」。冠軍賽給傳奇球團一個明確、可以達成的終點：

- 明確的資格：跟晉級一樣看「本聯盟場數 + 最近勝率」，再加上傳奇才有的競技積分
- 確定性的七戰四勝：同一個存檔、同一個操作，結果一定一樣；重新整理、換分頁都不會改變
- 可靠的存檔與重試：每一個操作都是冪等的，寫入失敗不回報成功，重試結果一樣
- 合理的難度：比傳奇聯盟的一般對手強，但不需要全隊 Lv.20
- 完全獨立：不影響放置結算、聯盟戰績與積分、收益、生涯數據、特性訓練、MVP

## 2. 資格（交付 1）

| 條件 | 數值 | 來源 |
|---|---|---|
| 所在聯盟 | 傳奇（tier 4） | — |
| 傳奇聯盟出賽 | ≥ 100 場 | 沿用 `PROMOTION_CONFIG.minMatches` |
| 最近 60 場勝率 | ≥ 60%（不足 60 場不算達標） | 沿用 `PROMOTION_CONFIG.window／winRate` |
| 競技積分 | ≥ 70 | 新增 `CHAMPIONSHIP_CONFIG.minPoints` |
| 冷卻 | 上一個系列賽結束後再打 288 場一般比賽（24 小時） | `CHAMPIONSHIP_CONFIG.retryAfterMatches` |

理由（數據見平衡報告 A 節）：

- **新晉級的球團不可能馬上有資格**：晉級時本聯盟場數歸零，至少要再打 100 場（約 8.3 小時）。6 個種子都沒有「晉級當下就有資格」。
- **到傳奇後多久有資格**：MVP 成長開啟時平均 17.6 天（6/6 個球團都達到），關閉時 15.3 天（5/6）。
- **積分門檻 70 從來不是卡住的條件**：門檻 0／60／70／80 的「第一次有資格」完全相同——最近 60 場勝率 ≥ 60% 時，積分（勝 +3、敗 −2）一定在 70 以上。保留它是因為它跟「保級安全」的意義一致，而且成本為零；如果之後積分規則改變，它會擋住「勝率剛好夠但積分在危險區」的球團。
- **冷卻 24 小時**：資格才是真正卡住第一座冠軍的條件（傳奇期間只有 11～17% 的時間有資格）。冷卻 8 小時時，強隊每次上線都能再打一輪（120 天最多 167 個系列賽、106 座冠軍），冠軍次數失去意義；改成 24 小時，第一次奪冠的天數、挑戰次數、30／60／90／120 天的奪冠人數都幾乎不變（平衡報告 D 節），重複奪冠降到最多 62 個系列賽。
- **MVP +0.3 不會讓資格過度提前**：MVP 成長讓「到傳奇」提早約 9 天（46.5 → 37.2 天），但「到傳奇後到有資格」沒有縮短（15.3 → 17.6 天，樣本小、差異在雜訊內）。

## 3. 狀態機（交付 2）

只有一個狀態機：`domain/championship.ts` 的 `championshipView(club)`。畫面、服務、測試都讀它，不另外判斷規則。

```
           到傳奇                  條件都達到             開始系列賽
 locked ─────────▶ not-eligible ─────────────▶ eligible ───────────▶ in-progress
   ▲                 ▲    │                      │  ▲                   │
   │ 降級（沒有進行中）│    │ 條件掉了              │  │ 冷卻結束          │ 先拿 4 勝 → 奪冠
   └─────────────────┴────┘◀─────────────────────┘  │                   │ 先輸 4 場 → 落敗
                                                    │                   ▼
                                               cooldown ◀──────── 系列賽結束（記錄、冷卻）
```

- `in-progress` 的優先權最高：系列賽進行中，不管聯盟、資格、冷卻怎麼變，都可以打完。
- 一場一場打：每次操作只打一場；第 n 場的請求只有在「進行中、已經打了 n−1 場」時才接受。
- 一方先拿到 4 勝就結束，不會有第 5 個勝場或敗場（服務拒絕、純函式丟錯、存檔驗證也拒絕）。
- 狀態全部由存檔推導：勝敗數由 `games` 算出，不另外存，不會不一致。

## 4. 冠軍隊的強度（交付 3）

`CHAMPIONSHIP_CONFIG.opponentMean = 7.1`（傳奇一般對手 6.6、傳奇的晉級挑戰 6.85）。

選擇依據（平衡報告 B、C 節）：

| 強度 | 第一次有資格的普通球隊：單場／系列賽 | Lv.20 全滿：系列賽 | 完整遊玩：奪冠前挑戰次數 | 第一次有資格 → 奪冠 |
|---|---|---|---|---|
| 6.9 | 39.0%／27.1% | 33.1% | 2.2 | 8.7 天 |
| **7.1** | **35.3%／20.5%** | **29.1%** | **1.6** | **5.1 天** |
| 7.3 | 32.3%／15.8% | 20.3% | 3.4 | 9.2 天 |

- 6.9 跟晉級挑戰（6.85）幾乎一樣，沒有「頂點」的感覺。
- 7.3 讓一個種子 120 天內拿不到冠軍，挑戰次數翻倍。
- 7.1：比傳奇一般對手明顯強（單場勝率從 45% 降到 35%），但第一次有資格時的普通球隊就有兩成機會、完整遊玩平均 1.6 次挑戰就能奪冠；**不需要全隊 Lv.20**（第一次有資格時，6 個種子的上場平均等級是 9.4～19.8，只有 1 個接近滿級；這些球團大多在第一次有資格後幾天內奪冠）。
- 沒有任何一種隊伍變化或戰術超過 30% 的系列賽勝率（不會有「一招必勝」）。

完整遊玩的系列賽勝率（約 50%）比 B 節（約 20%）高很多：完整遊玩是在「有資格時」開始，有資格本身就代表球隊正在熱手、而且球隊還在持續成長。兩個數字都報告，決策以 B 節（最保守的情況）為準。

冠軍隊：固定隊名「傳奇王朝」；陣容由球團種子與系列賽序號產生（`SEED_SALT.championshipOpponent`），**開始系列賽時整支存進存檔**，整個系列賽都是同一支（之後就算改了產生器也不變）。風格（打線流派）由陣容決定、只做顯示。不同系列賽是不同陣容，避免某一種戰術永遠剋同一支球隊。

## 5. 編號與種子（交付 4）

| 東西 | 規則 |
|---|---|
| 系列賽序號 | `championship.nextSeriesSeq`，開始時 +1，只增不減 |
| 系列賽 ID | `<clubId>#s<seq>` |
| 冠軍隊 | `deriveSeed(clubSeed, seq, SEED_SALT.championshipOpponent = 8)` → `generateTeam(rng, 7.1)` |
| 第 n 場比賽 ID | `<clubId>#s<seq>g<n>` |
| 第 n 場種子 | `deriveSeed(clubSeed, seq × 8 + n, SEED_SALT.championship = 7)` |
| 主客場 | 2-3-2：冠軍隊第 1、2、6、7 場主場，我方第 3、4、5 場主場 |

新的 salt（7、8）跟既有的一般比賽（0、1）、招募（2、5）、晉級挑戰（3、4）、潛能（6）都不重疊；比賽 ID 的 `#s` 也不會跟 `#c`（挑戰）或一般比賽重複。

## 6. 快照

- **冠軍隊**：開始系列賽時固定（整支 `Team` 存在 `active.opponent.team`）。
- **我方**：每一場開打時，用跟一般比賽同一個 `buildPlan` 快照當下的有效陣容（等級、特性、MVP 加成、裝備）與戰術。系列賽中途升級、換人、改戰術、完成訓練、MVP 成長，都從下一場開始生效；已經打完的場次不會重算。
- 這一場的結果在按下按鈕時就模擬並存檔；之後的「觀看」只是播放存好的 Replay（不先揭曉結果）。所以不需要 `liveMatch` 那種「進行中比賽固定計畫」。

## 7. 冪等與跨分頁（交付 5）

跟晉級挑戰（`leagueService`）同一套做法：

- 請求帶上「畫面顯示時」的序號（`seriesSeq`、`game`）與這次操作的 `requestId`（每按一次產生一個）。
- 全部在 ClubLock 裡：讀最新存檔 → `settleDueUnsaved` 結算到期的一般比賽 → 檢查 → 模擬 → 一次存檔（revision 檢查）。
- 序號等於存檔的值：執行。
- 是最近一次成功的請求（序號 + requestId 相同）：重送，回傳原本的結果，**不再模擬**。決定勝負那一場在系列賽結束後也辨認得出來（靠 `lastGame`）。
- 其他：`stale-request`，畫面重新讀取。兩個分頁同時按，只有一個成功。
- 控制器 single flight：連點只送一次。
- 結算失敗：打完的一般比賽照樣存檔，不打冠軍賽。冠軍賽模擬失敗：到期的一般比賽照樣存檔，這一場沒打（序號不變、可以重試，同一場一定同一個種子）。存檔寫入失敗：丟 `ClubSaveError`，什麼都沒變，不回報成功；重試得到完全一樣的結果。
- 拒絕之前已經結算並存好的一般比賽，會附在錯誤上（`settled`），畫面拿得到最新存檔。

## 8. 降級（交付 6）

全部由同一個狀態機處理：

| 情況 | 結果 |
|---|---|
| 還沒開始系列賽，降級 | 失去資格（`locked` + `relegated`），要回到傳奇、重新達到條件 |
| 系列賽進行中，降級 | 照樣可以打完（`in-progress` + `relegatedDuringSeries`，畫面有說明） |
| 系列賽打完 | 球團留在實際所在的聯盟（冠軍賽不改聯盟） |
| 冠軍賽結果 | 不計入聯盟戰績與積分，所以不會因為冠軍賽降級、也不能用冠軍賽保級 |
| 已經拿到的冠軍 | 永久保留（降級、再晉級都不影響） |

為什麼允許打完：系列賽一旦開始，冠軍隊已經固定、前面的場次已經打完；如果中途降級就作廢，玩家會因為一般比賽的結算時間（離線多久）失去已經打下來的戰績，這不公平也不直覺。反過來，還沒開始的系列賽沒有任何沉沒成本，用目前的資格判斷最簡單。

## 9. 首次奪冠（交付 7）

```ts
firstTitle: { seriesSeq, seriesId, at, wins, losses, clubId, clubName, matchIndexAt } | null
titles: number            // 累積冠軍次數
history: SeriesRecord[]   // 最近 10 個系列賽（比分、勝負、時間）
```

- 第一次奪冠時寫入，之後再奪冠不改（測試 20）。
- 獎勵採 **方案 A：只有榮譽**。不發資金與經驗，所以不需要碰經濟的不變量（收益 = 未領取 + 已領取、支出紀錄），也不會有「重複發獎」的風險。榮譽：首頁冠軍卡片、冠軍次數、首次奪冠日期與比分。外觀與慶祝演出在 PR 2。

## 10. 存檔 V14 與遷移（交付 8）

- `ClubSave.championship`：`{ nextSeriesSeq, active, history, titles, firstTitle, readyAt, lastGame }`。
- V13 → V14（`toV14`）：只加上空的 `championship`，其他欄位一個字都不動；`revision + 1`、`migratedFrom` 記原始版本。舊存檔不追溯補發冠軍——就算早就符合資格，也要自己打。
- 完整遷移鏈 V3～V13 → V14 都經過 `toV14`；原始文字逐字備份到 `backup-schema13`。
- `legacyV13.ts` 凍結 V13 的格式；`toV13` 改為不驗證的中間步驟。
- 驗證（`championshipIssues`）：序號單調、ID 跟球團一致、勝負跟比分一致、沒有和局、主客場符合 2-3-2、已結束的系列賽一定是打完的七戰四勝（最後一場之前沒有一方 4 勝）、進行中的系列賽不能已經有一方 4 勝、冠軍次數 ≥ 紀錄裡的冠軍、首次奪冠跟紀錄一致、`lastGame` 一定是進行中或最近結束的系列賽的最後一場。

## 12. 畫面

首頁（聯盟卡下面；電腦版第三欄）的「傳奇總冠軍賽」卡片：

- 不在傳奇也沒到過：不顯示
- 條件不足：三個條件的達成狀態與「還差 N 個條件」
- 有資格：「開始系列賽」→ 確認對話框（規則與獨立性）→ 開始
- 進行中：「目前戰績 2 勝 1 敗」「再贏 2 場即可奪冠・再輸 3 場就落敗」、七場格子、對手、「打第 N 場」、「觀看第 N 場」
- 打完一場：先問「觀看比賽／直接看結果」（不先揭曉），結果對話框顯示比分與系列賽戰績
- 奪冠：「恭喜！你已獲得傳奇總冠軍！」、系列賽比分、首次奪冠日期；卡片永久顯示冠軍紀錄
- 冷卻、降級、過期（別的分頁）、唯讀分頁、模擬失敗、寫入失敗：卡片狀態或提示訊息
- 沒有慶祝動畫（PR 2）
