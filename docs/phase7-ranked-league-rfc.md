# RFC：競技聯盟（積分、晉級、降級）

狀態：**待確認**。確認前不改 Domain、存檔、結算流程，也不把下面任何數字寫進遊戲 Config。
數據：[平衡報告](balance/v2-phase7-ranked-report.md)（45 天、每天上線 1／3／6 次、策略 B／E／D、種子 1～3，7 個方案共 189 次模擬，分段結算）。

> **這份 RFC 裡的模擬數字都是近似值**，只能用來比較方案之間的相對差異，不能當成上線後的精確預測：每格只有 9 次模擬、玩家行為是腳本化的、上線時間是理想化的。降級是少見事件，「有降級的球團 11～22%」這類數字只代表 1～2 個球團。詳見報告的「近似與限制」。

## 1. 目標與限制

- 挑戰者以上要有「每一場都算數」的感覺，但遊戲仍然是**放置＋輕度經營**：不能變成要一直盯著、怕離線就掉級。
- 積分與升降級只來自正式結算；重送、多分頁、離線結算、重新整理、Replay 都不能重複計分；Replay 中不做升降級判斷。
- 舊存檔照常可玩、不重發首次晉級獎勵、不會因為上線新規則就突然降級。

## 2. 現行規則（基準 BASE）

所有聯盟相同：本聯盟 100 場、最近 60 場勝率 ≥ 60% → 晉級挑戰賽（對手 = 下一級 +0.25）→ 失敗 12 場冷卻。沒有降級。
模擬顯示玩家會停在「勝率約五成」的聯盟：B／E 在職業 49～54%、傳奇 45～54%。

## 3. 方案

共通（所有積分方案）：積分 0～100、晉級或降級後從 50 開始、晉級後 20 場保護（積分不會低於 1）、挑戰者是保底、只有職業／傳奇會降級、降一級、首次晉級獎勵不重發。

| 方案 | 晉級條件（挑戰者以上） | 積分 | 降級 |
|---|---|---|---|
| **A 混合（需求文件建議）** | 積分 ≥ 80 ＋ 本聯盟 ≥ 30 場 ＋ 挑戰賽 | 從挑戰者開始；比較 +3／−2（設計稿示意）、+2／−2、+2／−1 | 職業／傳奇積分歸零 |
| **C 保級積分（本 RFC 建議）** | **維持現行** 100 場＋60%＋挑戰賽（所有聯盟一樣） | 只在職業、傳奇；勝 +3／敗 −2（損益兩平 40%） | 職業／傳奇積分歸零 |
| **B 賽季** | 維持現行 | 沒有積分 | 職業／傳奇每 100 場一季，季勝率 < 40% 降級；晉級後第一季不降 |

新秀、業餘在所有方案都維持現行規則、只升不降。

## 4. 比較

| 面向 | A +3／−2 | A +2／−2 | A +2／−1 | **C +3／−2** | B 賽季 |
|---|---|---|---|---|---|
| 進度速度（挑戰者→職業 P50，每天 3 次） | 1.0 天（基準 3.7） | 2.7 | 1.0 | **3.7（=基準）** | 3.7 |
| 有降級的球團 | 56% | 67～78% | 0～11% | **0～22%** | 11～67% |
| 職業／傳奇降級（每千場） | 0.2～0.23／0.08～0.25 | 0.65～1.08／0.28～0.68 | 0／0～0.01 | **0～0.07／0～0.02** | 0～0.25／0.1～0.34 |
| 平均降級次數（E 跟著建議，45 天） | 1.7 | 6.7 | 0 | **0** | 2.1 |
| 每天 1 次 vs 6 次的差距 | 跟基準差不多（場數決定） | 同左 | 同左 | 同基準 | 同基準 |
| 長時間離線的壓力（一次上線就從安全區被降級，每天 1／3／6 次） | 4／7、5／10、8／20 | 8／12、20／50、10／63 | 0／1 | 0／0、2／2、0／3 | 0（一季 100 場才判定） |
| 降級後重返（P50） | 0.6～3.1 天 | 0.8～2.3 天 | 4.2 天（1 次） | 3.3～6.3 天 | 1.8～1.9 天 |
| 跟現有晉級流程的相容性 | 要改 eligibility、首頁建議、聯盟卡 | 同左 | 同左 | **晉級完全不變**，只新增保級 | 晉級不變，新增季紀錄 |
| 技術複雜度 | 中：積分＋兩套 eligibility＋降級 | 同左 | 同左 | 中低：積分＋降級（不改 eligibility） | 中：季的游標、勝敗、保護 |
| 玩家體驗 | 晉級太快、常被降級（「升了又掉」） | 職業↔傳奇來回跳（每週好幾次） | 幾乎只升不降，積分沒意義 | 積分有意義但很少掉到危險區（≤ 1% 的場次） | 結果要等一季，回饋慢 |

結論：

1. **方案 A 用設計稿的示意數字（+3／−2）會讓晉級變得比現在容易很多**：損益兩平勝率只有 40%，而現行要 60%。挑戰者→職業從 3.7 天變 1.0 天，結果是 56% 的球團被降級、「升了又掉」。
2. **把積分調成對稱（+2／−2）會變成隨機漫步**：勝率五成的球隊會在職業和傳奇之間反覆升降，E 策略 45 天平均降級 6.7 次——最違反「不用一直盯著」。
3. **積分很難同時當晉級門檻和保級門檻**：門檻高就常掉級，門檻低就晉級太快。現行 60%／（降級 40%）之間的落差就是「遲滯區間」，讓球隊可以停在適合的聯盟。
4. **C 把兩件事分開**：晉級沿用 60%（完全不改現在的流程與進度速度），積分只負責「長期打不贏才降級」。45 天裡 E、D 策略從沒被降級，只有平均養成（B）的高頻玩家偶爾降級，3～6 天能回去。

## 5. 建議：方案 C（確認的話第二階段照這份實作）

| 參數 | 建議值 | 依據 |
|---|---|---|
| 有積分的聯盟 | 職業、傳奇（挑戰者不需要：它是保底） | 挑戰者不會降級，積分沒有作用 |
| 範圍 | 0～100 | 設計稿 |
| 起始／降級後／重返後 | 50 | 設計稿；模擬用 50 |
| 每場 | 勝 +3／敗 −2 | 損益兩平 40%：長期 < 40% 才會往下掉 |
| 危險區 | ≤ 20（只是提示，不影響規則） | 設計稿；C 只有 0～1% 的場次在危險區 |
| 降級 | 積分歸零的那一場之後降一級 | 判定點清楚、確定性 |
| 晉級後保護 | 20 場內積分最低 1 | 避免剛升上去就被一波連敗打回去 |
| 晉級 | 不變（100 場／60%／挑戰賽／12 場冷卻） | 相容、進度不變 |
| 首次晉級獎勵 | 每個聯盟一次（現行 `rewardedTiers`） | 設計稿：重返不再發 |
| 傳奇的長期目標 | 保級（積分）＋養成；不加新貨幣 | 設計稿 |

### 和需求文件的差異（請確認）

需求文件建議「挑戰者以上用積分晉級」。數據顯示這會讓進度變快、降級變多，所以建議改成 C。若仍想要「積分晉級區」的設計，替代做法是 **A'：晉級區 ≥ 80 ＋ 保留 100 場＋60%**，但這等於多一個幾乎一定同時達成的條件，對玩家沒有新資訊（未模擬）。

## 5A. 方案 D：保留現行晉級，從挑戰者開始顯示競技積分（評估，不是正式規則）

D 的內容：保留 100 場＋最近 60 場勝率＋晉級挑戰賽；**從挑戰者聯盟開始提供競技積分**；職業與傳奇有降級風險；挑戰者是保底。
跟 C 唯一的差別是挑戰者也有（顯示）積分。挑戰者不會降級、積分也不是晉級條件，所以 D 跟 C 的比賽、進度、降級**完全相同**，模擬用同一組（`C+3-2`），差別只在玩家看到什麼。

| 問題 | C（積分只在職業／傳奇） | D（積分從挑戰者開始） |
|---|---|---|
| 一般玩家感受得到積分成長嗎？ | 職業 89%、傳奇 91% 的場次積分 ≥ 80：升上去之後幾場就漲到接近 100，之後大多停在頂端 | 挑戰者也一樣：92% 的場次 ≥ 80。兩者都是「前幾十場有成長感，之後幾乎一直滿格」 |
| 積分與晉級目標容易理解嗎？ | 積分只代表「保級安全度」，晉級另外看 100 場／60%，兩件事分開 | 挑戰者的積分不會降級、也不影響晉級，對玩家來說是「沒有作用的分數」，需要額外說明 |
| 降級會不會太頻繁？ | 不會（45 天 5 次，都是 B 策略的高頻玩家） | 同 C（挑戰者不會降級） |
| 保留放置遊戲的輕鬆嗎？ | 是：危險區場數 ≤ 1%，E、D 策略沒有降級 | 同 C |
| 需要額外的保級緩衝嗎？ | 不一定：緩衝一次（C+3-2r）只把降級 5 → 4 次；可以當成心理上的安全網，不是必要 | 同 C |
| 會不會產生重複或矛盾的晉級條件？ | 不會，只要**不顯示「晉級區」**：積分 ≥ 80 跟晉級無關 | **會，如果沿用設計稿的「晉級區 80」**：76% 的上線檢查看到「積分在晉級區、但 100 場／60% 還沒達成」（相反情況 0%）。等於畫面上同時有兩個晉級目標、而且常常互相矛盾 |

評估結論：

1. D 的進度、降級壓力跟 C 一樣輕；差別全在畫面。
2. D 如果要做，挑戰者的積分要**拿掉「晉級區」**，只當「競技表現」顯示（例如「挑戰者保底中」），否則會跟 100 場／60% 互相矛盾。
3. 用 +3／−2，大部分時間積分是滿的，D 的「成長感」只有剛升上挑戰者的前 10～20 場。若要成長感更持久，要換另一種刻度（例如較小的每場增減或較高的上限），但那會改變職業／傳奇的保級節奏，需要另外模擬。
4. 所以 RFC 仍建議 C；D 可以當成 C 的 UI 變化（挑戰者先顯示積分、只說明「保底」），**不建議當成另一套規則**。

## 6. 正確性與存檔（第二階段）

- **資料**：`LeagueState` 新增 `points: number`、`protectLeft: number`、`relegations: number`、`lastRelegation: { atMatch, fromTier } | null`。schemaVersion 8 → 9。
- **計分只在 `settleOutcomes`**：跟 `recordLeagueResult` 同一個地方、同一個條件（`plan.leagueTier === league.tier`）。已結算的場次（`matchIndex < nextMatchIndex`）直接略過，所以重送、多分頁（Web Locks＋revision）、重新整理都不會重複計分。Replay 只讀 `replays`，不經過結算。
- **降級發生在一批離線結算的中間**：目前一批的比賽都用開始時的聯盟規劃。第二階段把 `settleDueUnsaved` 改成「降級那一場之後的比賽重新規劃」（只會發生一次，因為降級後 20 場保護）。固定的進行中比賽（liveMatch.plan）照開賽時的聯盟算，不計分。
- **挑戰賽不影響積分**：只有一般比賽計分；晉級成功時重設為 50＋保護。
- **不變量**：`tier ≤ highestTier`、`promotions ≥ highestTier`、`0 ≤ points ≤ 100`、`tier < 3 ⇒ points = 50`（或不使用）、`rewardedTiers ⊆ [1, highestTier]`。
- **遷移（8 → 9）**：所有舊存檔 `points = 50`、`protectLeft = 20`（上線後先保護 20 場）、`relegations = 0`；`highestTier`、`promotions`、`rewardedTiers` 原樣。**遷移不看舊戰績**，所以不會有人一上線就被降級；首次晉級獎勵用 `rewardedTiers` 判斷，不會重發。遷移前一樣保留原始文字備份（沿用 3～7 的做法）。
- **介面**：直播卡結束列 ±分、聯盟卡（保級安全／危險區／降級後三態）、Toast（進入／離開危險區）、降級對話框（保留清單、新目標）。晉級相關畫面不變。

## 6A. 模擬方法的限制（P2-2）

- 第一版的模擬（整批近似）是在一次上線的離線結算全部完成後才算積分與降級，降級之後同一批剩下的比賽仍用舊聯盟的對手（強 0.4）與收益倍率（例如職業 ×1.45 而不是挑戰者 ×1.30），而且不計分。
- 這版改成**分段結算**（只改模擬腳本，沒有改 Domain）：每段最多結算到「最早可能歸零的那一場」，降級後下一段由正式的 `settleDue` 用新聯盟規劃，效果等同第 6 節的「降級後重新規劃」。
- 兩種方法的比較（報告「分段結算與整批近似的差異」）：C 的數字幾乎相同；A+2-2 這種頻繁升降的方案，整批近似低估了「一次上線就被降級」（每天 3 次 15 → 20）與每天 1 次的重返時間（4.0 → 2.3 天）。批次越大（每天上線越少，96 場）偏差越大。
- 仍然只是近似：玩家行為是腳本化的、上線時間是理想化的、樣本小；也沒有涵蓋進行中比賽的固定計畫、多分頁鎖與 revision。**所有天數、比例都只能看相對大小。**
