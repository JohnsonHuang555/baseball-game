# Phase 8 統計規格（Statistics Specification）

> 對象：`src/sim/game.ts`（規則版本 1～9）、V2 放置經營的正式結算。
> 原則：**數據只來自正式比賽的事件，不為了填滿畫面製造數字**；加入統計不能改變任何比賽結果。

## 1. 盤點：模擬引擎實際有哪些事件

`Game.finishPlay()` 是每個打席唯一的出口，打席結果是 `PlayKind`：

| PlayKind | 實際內容（引擎行為） | 打者 | 跑者 |
|---|---|---|---|
| `single` `double` `triple` `homeRun` | 安打；跑者推進由亂數決定 | 上一、二、三壘／得分 | 依推進 |
| `groundOut` | 滾地出局，**打者一定出局**；被迫跑者推進 | 出局 | 被迫者推進、其他看情況 |
| `doublePlay` | 三種：滾地雙殺（一壘跑者＋打者）、外野接殺＋本壘觸殺、平飛接殺＋跑者回不去 | 出局 | 一位跑者出局 |
| `flyOut` `lineOut` | 接殺 | 出局 | 可能推進 |
| `sacrificeFly` | 外野接殺、三壘跑者回壘觸壘得分（兩出局前） | 出局 | 三壘得分 |
| `strikeout` | 三振（含兩好球觸擊界外） | 出局 | — |
| `walk` `intentionalWalk` | 四壞、故意四壞 | 上一壘 | 被迫推進 |
| `sacrificeBunt` | 觸擊成功：打者出局、所有跑者推進一個壘 | 出局 | 推進 |
| `buntPopOut` | 觸擊小飛球被接 | 出局 | — |
| `error` | **打者因守備失誤上壘**（ROE）；內野失誤跑者推進 1 個壘，外野推進 2 個壘 | 上一或二壘 | 推進 |

其他會改變壘包或出局數的事件：

- **盜壘**（`steal`）：只能從一壘、二壘盜，成功前進一個壘，失敗（盜壘刺）出局。**不會得分**。打帶跑揮空時也是走盜壘。
- **延長賽突破僵局**：第 10 局起每個半局開始，上一棒放在二壘（`endHalfInning`，沒有事件）。
- **換人**：代打、代跑、守備替補、換投（`substitution` 事件）。**教練可以在打席中途（球數不是 0-0）換投、派代打。**

引擎**沒有**的事件（所以統計一律是 0，不是「沒記錄」）：觸身球、野選（Fielder's Choice）、暴投、捕逸、投手犯規、牽制、跑壘中的失誤、打擊妨礙、不死三振、內野高飛必死球。
這些都不是「漏記」：引擎根本不會產生這種結果。若之後的規則版本加入，統計要跟著加，不能用其他欄位代替。

## 2. 目前已經有、但不夠的資料

`PlayerLine`（每場一份，用在錦標賽成長、MVP、潛力）：

- 打者：`pa hits hr rbi so`
- 投手：`outs runs k`

不能直接拿來算的原因：

| 想要的 | 不能用 | 原因 |
|---|---|---|
| AB | `pa` | PA 含保送、犧牲打、犧牲飛球 |
| 1B／2B／3B | `hits` | 沒分安打種類，算不出壘打數與長打率 |
| BB | — | 沒有保送欄位 |
| SF | — | 沒有，OBP 分母需要 |
| 投手 IP | `outs` | `outs` **沒有算盜壘刺殺**造成的出局 |
| 投手 H／BB | — | 沒有 |
| ER | `runs` | `runs` 是失分；也沒算到「跑者是誰放上壘的」，換投後失分記錯人（記在當時投球的投手） |

V2 存檔的 Box Score 只存名字與 `[pa, hits, hr, rbi, so]`、`[outs, runs, k]`，同樣不夠。

**決定：`PlayerLine` 不改**（舊行為、舊錦標賽成長與 Golden 都不變），另外加一份完整的計分紀錄 `ScoreLine`（`src/sim/scoring.ts`）。

## 3. 各項統計的正式定義與引擎對應

### 3.1 打者

| 欄位 | 正式定義 | 引擎來源 | 可正確計算 |
|---|---|---|---|
| G | 出場（先發打線、代打、代跑、守備替補都算） | 開賽打線＋`substitution`（pinchHit／pinchRun／defense） | ✅ |
| PA | 完成的打席 | 每次 `finishPlay` | ✅ |
| AB | PA − BB − HBP − SF − SH − 打擊妨礙 | 依 PlayKind（見下） | ✅ |
| H、1B、2B、3B、HR | 安打與種類 | `single/double/triple/homeRun` | ✅ |
| R | 跑者回本壘得分 | 跑壘移動 `to: 4`（第三個出局那一球的得分不算，跟引擎一致） | ✅ |
| RBI | 打點 | 沿用引擎規則：失誤、雙殺不算打點；其他打席的得分都算 | ✅（見 §6 限制） |
| BB／IBB | 四壞（含故意四壞）／故意四壞 | `walk`、`intentionalWalk` | ✅ |
| HBP | 觸身球 | 引擎沒有 | ✅ 永遠 0 |
| SF | 高飛犧牲打 | `sacrificeFly` | ✅ |
| SH | 犧牲觸擊 | `sacrificeBunt` | ✅ |
| SO | 三振 | `strikeout` | ✅ |
| GIDP | 滾地雙殺打 | `doublePlay` 且擊球是滾地球 | ✅ |
| ROE | 因失誤上壘（算打數、不算安打、不算上壘率） | `error` | ✅ |

**AB 的 PlayKind**：安打 4 種、`groundOut`、`flyOut`、`lineOut`、`strikeout`、`buntPopOut`、`doublePlay`、`error`。
**不算 AB**：`walk`、`intentionalWalk`、`sacrificeFly`、`sacrificeBunt`。

恆等式（每場、每位打者都必須成立，測試會檢查）：

```
PA = AB + BB + HBP + SF + SH
H  = 1B + 2B + 3B + HR
```

公式：

```
TB  = 1B + 2·2B + 3·3B + 4·HR
AVG = H / AB
OBP = (H + BB + HBP) / (AB + BB + HBP + SF)
SLG = TB / AB
OPS = OBP + SLG
```

### 3.2 投手

| 欄位 | 正式定義 | 引擎來源 | 可正確計算 |
|---|---|---|---|
| G | 登板 | 先發＋換投 | ✅ |
| BF | 面對打者數 | 每次 `finishPlay`（記給「該為這個打者負責」的投手，見 §4.4） | ✅ |
| Outs | 投球期間守備方製造的出局數 | 打席的出局＋**盜壘刺殺** | ✅ |
| IP | Outs / 3；顯示 `6.2` = 6⅔ 局 | 由 Outs 換算 | ✅ |
| H、HR | 被安打、被全壘打 | 安打 PlayKind | ✅ |
| BB／IBB | 投出的保送 | `walk`、`intentionalWalk` | ✅ |
| HBP | 觸身球 | 引擎沒有 | ✅ 永遠 0 |
| K | 三振 | `strikeout` | ✅ |
| R | 失分：得分記給**放這位跑者上壘的投手** | 跑者責任追蹤（§4） | ✅ |
| ER | 自責分 | 跑者責任＋半局重建（§4） | ✅（見 §4 與 §6） |

公式：

```
IP   = Outs / 3                （顯示：⌊Outs/3⌋ . (Outs mod 3)）
ERA  = ER × 27 / Outs
WHIP = (BB + H) × 3 / Outs
```

### 3.3 零分母

所有比率在分母為 0 時回傳 **`null`（unavailable）**，畫面顯示「—」。不會出現 `NaN`、`Infinity`、`.000`、`0.00`。

| 指標 | 分母 | 例子 |
|---|---|---|
| AVG、SLG | AB | 只有 2 次保送：AVG、SLG 是「—」，OBP 是 1.000 |
| OBP | AB + BB + HBP + SF | 只有 1 次犧牲觸擊：PA = 1，但 OBP 分母 0 → 「—」 |
| OPS | OBP、SLG 任一個是 null 就是 null | |
| ERA、WHIP | Outs | 登板但一個出局都沒抓到：ERA「—」，不是 ∞ |

比率一律用**累積的原始數據**重算，不平均每場的比率（近期、生涯、排行共用 `src/v2/domain/stats.ts` 同一組函式）。

## 4. 失分與自責分（ER）

### 4.1 參考的正式規則（OBR 9.16）

> 自責分**依遊戲記分規則計算**：下列規則能在這個引擎的事件裡確定判斷的部分照做，需要記錄員判斷的部分採固定、可測試的做法（見 §4.3、§6）。不宣稱與正式記錄員的判定完全一致。


1. 跑者因失誤上壘，他得分是非自責分。
2. 半局重建：把失誤當作本來該發生的出局。重建後應該已經三出局，之後的得分全部是非自責分。
3. 因失誤才得分（失誤那一球直接回來）是非自責分。
4. 換投：場上的跑者仍屬於放他上壘的投手（繼承跑者）；他得分算前一位投手的失分。
5. 後援投手**不能享有**他上場前的失誤機會（9.16(i)）：重建只算他上場後的失誤。
6. 打席中途換投，球數 2-0、2-1、3-0、3-1、3-2 時打者被保送，這次保送與這位跑者記給前一位投手（9.16(h)）；其他結果記給新投手。
7. 延長賽二壘跑者：視同因失誤上壘，得分是非自責分，責任屬於放上去時在場的投手。

### 4.2 在這個引擎裡能確定判斷的部分

引擎的失誤**只有一種**：打者因失誤上壘（ROE），在打席結束時一次結算。沒有跑壘中的失誤、暴投、捕逸，也沒有野選。所以：

- 「本來該出局的機會」= 這個半局（或這位投手上場後）的 ROE 次數。
- 失誤造成的額外推進只發生在 ROE 那一球。
- 跑者身分不會在打席中改變（沒有野選換掉前位跑者），責任投手不會轉移。

實作（`Scorekeeper`，純記錄，不呼叫亂數）：

```
每位壘上跑者：{ 責任投手, earnedReach }    // ROE、延長賽二壘跑者 → earnedReach = false
半局狀態：chances = 本半局 ROE 次數；entryChances[投手] = 他上場時的 chances（半局開始在場的是 0）

一位跑者得分（這球不是第三個出局）：
  P = 跑者的責任投手；R[P] += 1
  重建出局數 = 這球之前的出局數 + (chances − entryChances[P])
  自責 ⇔ earnedReach && 這球不是 error && 重建出局數 + 這球造成的出局數 < 3
        （重建後這一球本身就是第三出局，例如高飛犧牲打的接殺、雙殺打的第二個出局，跑者不會回來）
  自責 → ER[P] += 1
這球是 error → 之後 chances += 1
半局結束 → 全部清空
代跑 → 跑者紀錄整筆轉給代跑者（責任與自責與否不變）
```

### 4.3 逐情境驗證（PR #18 review）

`src/sim/earnedRuns.test.ts`：每個情境用「正式引擎會產生」的事件序列寫單元測試；另外打 900 場真實模擬比賽，
用只看事件流、跟 Scorekeeper 無關的獨立計算，逐分比對「誰得分、失分記給誰、上壘方式、出局數、重建出局數、自責與否」，
並確認每一種情境都真的在比賽裡出現過。

| # | 情境 | 引擎會不會發生 | 處理 | 結果 |
|---|---|---|---|---|
| 1 | 無失誤半局 | 會 | ER = R | 正確 |
| 2 | 失誤上壘的跑者得分 | 會 | 非自責 | 正確 |
| 3 | 兩出局後失誤、接著全壘打 | 會 | 重建已三出局，非自責 | 正確 |
| 4 | 失誤讓跑者多推進 | 會（外野失誤推進 2 個壘、內野 1 個壘） | **不扣掉多推進的壘包** | **已知限制，可能高估**（§6-3） |
| 5 | 雙殺機會發生失誤 | 會（失誤在判斷雙殺之前決定） | 失誤只算 1 個出局機會，不假設雙殺 | 固定規則（§6-4） |
| 6 | 換投前留下的繼承跑者得分 | 會 | 算前一位投手 | 正確 |
| 7 | 換投前後都有失誤 | 會 | 前一位投手用完整半局重建、後援只算上場後的失誤（9.16(i)） | 正確 |
| 8 | 延長賽二壘跑者得分 | 會 | 非自責、算放上去時在場的投手 | 正確 |
| 9 | 高飛犧牲打（或雙殺打）與失誤 | 會 | 重建後這一球就是第三出局 → 非自責 | **修正**（之前漏算這一球的出局） |
| 10 | 第三個出局那一球的跑者 | 會 | 不算失分 | 正確 |

**修正前的錯誤（情境 9）**：判斷自責時只用「這一球之前」的重建出局數，沒有加上這一球本身造成的出局。
重建後已經 2 出局時的高飛犧牲打、重建後 1 出局時的滾地雙殺，跑者在重建裡不會回來，卻被算成自責。
Golden 的 160 場裡有 3 分（2 分高飛犧牲打、1 分雙殺打），900 場裡約 27 分（0.4%）受影響。只改記分，比賽、事件、亂數都不變。

### 4.4 規則版本與舊 Replay

- 計分只讀引擎狀態、不呼叫 `Rng`、不改變事件流；**不需要新的規則版本**。
- 用 `replay()` 重播任何規則版本（1～9）的舊比賽，都會得到同樣的比賽，並同時算出完整統計。
- Golden Test（`src/sim/__golden__`、`src/v2/application/__golden__`）鎖住 160 場模擬（9 種規則版本、含延長賽與疲勞換投）的事件流、比分、PlayerLine，以及 3 個球團共 336 場的勝負、收益、競技積分；加入統計前後一字不差。

### 4.5 打席中的換人

- 換投（9.16(h)）：見 §4.1-6。
- 代打（9.15(b)）：被換下的打者已經兩好球，代打者被三振，**三振與打數記給原打者**；其他結果記給代打者。
- 這兩種情況只會發生在「教練在打席中途下指令」，自動教練與內建 AI 都在打席開始時換人，仍然實作並有測試。

## 5. 期間、生涯與存檔

- **生涯**：以 `playerId` 為 key 的累計原始數據（`ClubSave.stats.players`），只在正式結算時累加；挑戰賽與重播不算。
- **最近 10／30 場**：球團最近已結算的 10／30 場**一般正式比賽**（不含晉級挑戰），每場在 `SettledMatch.lines` 存每位我方球員的精簡原始數據；沒上場的球員不增加 G／PA／Outs，但那場仍佔視窗。
- **記錄起點**：`stats.sinceMatch`。新球團是 0；V9 舊存檔遷移時是當時的 `nextMatchIndex`。起點之前的比賽**不回填、不重新模擬**，畫面標「記錄以來」。
- **防重複**：生涯與 `idle.nextMatchIndex` 在同一次狀態轉換裡前進；`stats.throughMatch` 必須等於 `nextMatchIndex`（存檔驗證），同一場不會累加兩次。
- **晉級挑戰賽**：不算進期間與生涯（另有挑戰紀錄）。

## 6. 已知限制

1. **RBI 與失誤**：引擎沒有「三壘跑者無論如何都會回來」的判斷，所以 ROE 那一球的得分一律不給打點（正式規則由記錄員判斷，可能會給）。沿用引擎原本的打點規則。
2. **ROE 那一球的得分**一律視為非自責（規則 9.16(a)「因失誤協助得分」；記錄員可能判定跑者本來就會回來，這裡採保守、可驗證的做法）。
3. **失誤造成的額外推進（情境 4）**：ROE 讓壘上跑者多推進的壘包，之後該跑者得分時，不另外重建「他本來在哪個壘」。
   正式規則要記錄員判斷「沒有失誤時跑者會到哪裡」、並對投手有利地推定；引擎的推進是亂數，重建之後每一球的推進都要猜，
   猜「回不來」會低估、不猜會高估，兩者都不完全正確。這裡採「不扣除」：**方向是 ER 可能偏高**（對投手偏嚴）。
   900 場真實模擬裡，這類「多推進後得分、仍算自責」的分約占全部失分的 0.7%（測試會印出實際比例，超過 2% 會失敗）。
   每一分都在記憶體的 `runLog` 標記 `errorBases`，之後要改規則時可以直接量化影響。
4. **雙殺機會發生失誤（情境 5）**：失誤一律只當作 1 個本來的出局，不推定會形成雙殺（引擎在決定失誤之前不會判斷雙殺）。
   如果記錄員判定本來會是雙殺，正式的 ER 會更少，所以這裡也是可能偏高的方向。
4. 勝敗投、救援、守備率、盜壘數不在這一階段。
5. Phase 8 之前的比賽沒有個人數據；最近 50 場的舊 Box Score 只有 `[pa, hits, hr, rbi, so]`，戰報裡其他欄位顯示「未記錄」。
