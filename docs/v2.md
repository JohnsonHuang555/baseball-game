# 骰子棒球 V2：放置經營（開發說明）

V2 是放置型的棒球經營：玩家管理球團、陣容與戰術，比賽由自動教練打完，每 5 分鐘一場，離線也會繼續（最多算 8 小時）。V1（逐球操作的原版）完全保留；首頁最上面是 V2 入口，網址 `#v2` 會直接進 V2。

## 功能

| 功能 | 說明 |
|---|---|
| 建立球團 | 第一次進入時建立，初始 14 人（9 先發、2 板凳、1 先發投手、2 後援）由既有產生器產生 |
| 自動比賽 | 每 5 分鐘一場，用 V1 的模擬引擎與自動教練；離線最多算 8 小時（96 場） |
| 收益 | 每場給資金與經驗，結算後要「領取」才會變成可以花的資產 |
| 球員養成 | Lv.1～20，花資金與經驗升級，能力依流派成長、逐級遞減、上限 10；升級後從下一場尚未打的比賽開始生效 |
| 招募 | 花資金招募打者或投手（Lv.1），先放進預備名單；球團最多 30 人 |
| 釋出球員 | 預備名單的球員可以釋出（二次確認、不可復原、不退款），空出名額再招募；上場球員要先換下來 |
| 聯盟晉級 | 新秀／業餘／挑戰者／職業／傳奇 5 個聯盟，越高對手越強、收益越多；本聯盟 100 場且最近 60 場勝率 ≥ 60% 可以挑戰下一聯盟（一場挑戰賽，贏了晉級並拿到第一次晉級獎勵）。沒有降級 |
| 陣容 | 換人上場（含預備名單）、交換守位或棒次、換先發投手、最多羈絆排法；從下一場開始生效 |
| 戰術 | 初版均衡戰術：跑壘積極度、後段調度、犧牲觸擊 |
| 戰報 | 近期 50 場摘要，最近 3 場可以看每局比分與個人成績 |
| 觀戰 | 用 V1 的球場動畫重播已經打完的比賽（最近 3 場與最近一次晉級挑戰）：暫停／繼續、1×／2×／4×、重新播放、跳到結束；唯讀，不影響球團與存檔 |

## 程式結構（`src/v2/`）

| 目錄 | 內容 |
|---|---|
| `domain/` | 純資料與純函式：存檔格式（`club.ts`）、聯盟（`league.ts`、`leagueConfig.ts`）、養成（`progression.ts`、`progressionConfig.ts`）、招募（`recruitment.ts`）、陣容（`lineup.ts`、`roster.ts`）、戰術、遷移（`migration.ts`、`legacyV3.ts`、`legacyV4.ts`）、獎勵與常數（`config.ts`、`rewards.ts`） |
| `application/` | 自動教練、比賽執行、放置時間、批次、結算、領取、升級／招募／釋出（`economyService.ts`）、晉級挑戰（`leagueService.ts`）、觀戰時間軸與播放狀態機（`replayPlayer.ts`）、建立／重設／遷移入口（`clubLifecycle.ts`） |
| `infrastructure/` | localStorage 存檔、Web Locks、依賴組裝（`createV2Deps`）、系統時間 |
| `ui/` | 控制器（不依賴 DOM）與各個畫面；觀戰畫面 `replayView.ts` 是動態載入的獨立 chunk，跟 V1 共用 `src/ui/playAnimation.ts`、`FieldRenderer`、`PitchCam` |

設計決策見 ADR-0007（自動比賽）、0008（放置結算）、0009（可玩 MVP）、0010（養成、招募、經濟、遷移）、0011（聯盟晉級、釋出球員、V5 遷移）、0012（觀戰、V6 遷移）。

## 存檔

- localStorage key `dice-baseball.club.v3`，目前是 schemaVersion 6。舊的 schemaVersion 3、4、5 會在進入 V2 時自動升級，原始文字依來源版本備份在 `dice-baseball.club.v3.backup-schema3`、`…backup-schema4`、`…backup-schema5`（已經有別的球團的備份時不覆寫，改存到帶 revision 的 key）。
- 完整 Replay 只保存最近 3 場一般比賽（每場約 7 KB）與最近一次晉級挑戰賽；觀戰不寫入存檔。
- V2 不讀也不改 V1 的任何存檔。
- 所有寫入都在 ClubLock（Web Locks）內「讀最新存檔 → 計算 → 存檔」，並有 revision 檢查；不支援 Web Locks 的瀏覽器同一時間只允許一個分頁寫入。

## 指令

| 指令 | 用途 |
|---|---|
| `npm run test` | 全部測試（V1 + V2） |
| `npm run build` | 型別檢查並打包 |
| `npm run bench:v2` | 單場模擬效能 |
| `npm run bench:v2:idle` | 放置結算效能、存檔大小、滿員 30 人的升級與招募耗時、最高聯盟長期遊玩的挑戰／釋出耗時與存檔大小、單場 Replay 大小與建立觀戰時間軸的耗時 |
| `npm run balance:v2` | 養成、招募、經濟、聯盟晉級的平衡模擬（4 種玩家策略、30 天、3 個種子）；可用 `SESSIONS`（每天上線次數）、`DAYS`、`SEEDS=101,202` 調整 |

## 調整數值

- 比賽獎勵：`src/v2/domain/config.ts` 的 `REWARD_CONFIG`
- 升級成本、成長幅度、招募成本、人數上限：`src/v2/domain/progressionConfig.ts`
- 聯盟名稱、對手強度、收益倍率、晉級獎勵、晉級條件、挑戰對手強度、失敗冷卻：`src/v2/domain/leagueConfig.ts`

改完先跑 `npm run balance:v2` 看各策略的進度與勝率；改成長公式會影響之後所有比賽，但已經打完的比賽不會變。
