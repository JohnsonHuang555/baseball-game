# 骰子棒球：放置經營（開發說明）

V2 是放置型的棒球經營：玩家管理球團、陣容與戰術，比賽由自動教練打完，每 5 分鐘一場，離線也會繼續（最多算 8 小時）。

從 Phase 6D 起網站只有 V2：開 `/` 直接進入，舊網址 `/#v2` 也會進來並自動清掉 `#v2`；V1（逐球操作的錦標賽／自由練習）已經移除（ADR-0016）。程式碼與文件裡的「V2」指的就是這個遊戲。

## 功能

| 功能 | 說明 |
|---|---|
| 建立球團 | 第一次進入時建立，初始 14 人（9 先發、2 板凳、1 先發投手、2 後援）由既有產生器產生 |
| 自動比賽 | 每 5 分鐘一場，用 `src/sim` 的模擬引擎與自動教練；離線最多算 8 小時（96 場） |
| 收益 | 每場給資金與經驗，結算後要「領取」才會變成可以花的資產 |
| 球員養成 | Lv.1～20，花資金與經驗升級，能力依流派成長、逐級遞減、上限 10；升級後從下一場尚未打的比賽開始生效 |
| 招募市場 | 選打者或投手 → 三位候選人（總評、能力、流派與特性，以及跟目前陣容的比較：打者比同守位的先發、投手比先發或最弱的後援）→ 選一位 → 確認簽約才扣資金（2,000 起，每次 +200，不花經驗；Phase 9 由 +400 下修，見 docs/phase9-gameplay-rfc.md）。候選人由球團種子、招募次數、角色與候選位置推導，關閉、重開、重新整理都是同一批；新球員 Lv.1，先放進預備名單、不自動上場；球團最多 30 人（ADR-0017） |
| 釋出球員 | 預備名單的球員可以釋出（二次確認、不可復原、不退款），空出名額再招募；上場球員要先換下來 |
| 聯盟晉級 | 新秀／業餘／挑戰者／職業／傳奇 5 個聯盟，越高對手越強（對手能力中心 5.0／5.4／5.8／6.2／6.6，Phase 6C 調整）、收益越多；本聯盟 100 場且最近 60 場勝率 ≥ 60% 可以挑戰下一聯盟（一場挑戰賽，贏了晉級並拿到第一次晉級獎勵）。沒有降級 |
| 陣容 | 換人上場（含預備名單）、交換守位或棒次、換先發投手、最多羈絆排法；從下一場開始生效 |
| 特性養成 | 球員詳情的「特性養成」（Phase 9 PR 3）：每位球員有確定性的潛能池（3 個正面特性候選），原生負面特性可以改善；全球團一個訓練槽，正式比賽實際出場才累積進度，完成後下一場起生效；正面特性上限 3 個（原生也算）。設計見 `docs/phase9-gameplay-rfc.md` §4、平衡見 `docs/balance/v2-phase9-traits.md` |
| 戰術 | 四種球隊風格（均衡、強攻、機動、守備，Phase 9 PR 2），依上場陣容推薦一種；進階設定：跑壘積極度、後段調度、犧牲觸擊（改了標「自訂」、可恢復預設）。戰報有「本場戰術」：實際的盜壘、觸擊、打帶跑、換投、守備替補、代打、代跑次數。設計見 `docs/phase9-gameplay-rfc.md` §3、平衡見 `docs/balance/v2-phase9-tactics.md` |
| 目前比賽（直播） | 首頁顯示進行中那一場的比分、局數、出局、壘上與剩餘時間；「觀看比賽」用共用的球場動畫（`src/ui/field.ts`、`pitchCam.ts`）直播，進來就是目前的進度，暫停只停自己的畫面；唯讀，不影響結果與獎勵 |
| 戰報 | 最近 50 場的數據戰報：日期、聯盟、對手、比分、每局比分、安打、失誤、我方打者與投手成績、精彩事件、收益（結算時存的 Box Score） |
| 直播的精彩時刻（Phase 6B） | 全壘打（分一般與滿貫）、再見（安打、全壘打、滿貫）、追平、超前、逆轉、得分、三振（揮空或站著不動）、雙殺各有演出；我方振奮、對手客觀；7 局以後得點圈有人、這個打席有機會追平或超前時顯示「關鍵打席」；半局結束、比賽進入後段、最終局、延長賽、換投有短暫轉場。所有揭露結果的畫面都在那一格正式提交之後，最終勝負在比賽結束時間之後 |
| 成長回饋（Phase 6C） | 養成畫面顯示升級後的球隊戰力，以及「同樣的經驗升別人明顯比較划算」的提示；首頁球隊區塊顯示最近 10 場與前 10 場的戰績（註明不一定由升級造成） |
| 晉級挑戰的觀看 | 按下挑戰後先問要看過程還是直接看結果；結果已經存檔，觀看可以暫停、調速度、直接看結果 |
| 首頁（Phase 6A） | 由上到下：目前比賽 → 目前建議 → 新手任務 → 球隊與養成 → 聯盟進度 → 未領取收益 → 最近比賽；只有目前比賽與目前建議用醒目的樣式 |
| 目前建議 | 固定規則挑一件「現在做得到」的事（領取 > 挑戰聯盟 > 培養球員 > 檢查陣容 > 觀看比賽），同一時間只有一個；按鈕只帶玩家過去，升級、挑戰仍要在原本的畫面確認 |
| 新手任務 | 建立球隊、觀看一場比賽、完成第一場、領取收益、培養一名球員、調整陣容；不限順序、完成自動打勾、可以收起，全部完成後收起就不再出現；不影響任何功能 |
| 網站入口（Phase 6D） | `src/main.ts` 載入共用樣式後呼叫 `startV2`（`ui/entry.ts`）；只建立一次 App，不監聽 hashchange；V2 沒有返回按鈕，Escape 不會關閉 App（觀戰畫面與對話框仍用 Escape 關閉） |
| 升級預覽 | 球員養成畫面顯示 Lv.N → Lv.N+1、會提升的能力與變化量、整體能力；升級成功後說明從第幾場生效 |

## 程式結構（`src/v2/`）

`src/sim/`（模擬引擎）與 `src/ui/`（觀戰球場、頭像、等級、對話框等共用元件與 `shared.css`）在 `src/v2/` 外面，路徑沿用 V1 時期的位置。

| 目錄 | 內容 |
|---|---|
| `domain/` | 純資料與純函式：存檔格式（`club.ts`）、聯盟（`league.ts`、`leagueConfig.ts`）、養成（`progression.ts`、`progressionConfig.ts`）、招募候選名單（`recruitment.ts`）與跟陣容的比較（`recruitCompare.ts`）、陣容（`lineup.ts`、`roster.ts`）、戰術、遷移（`migration.ts`、`legacyV3.ts`～`legacyV11.ts`）、特性養成（`traitTraining.ts`）、新手任務（`onboarding.ts`）、獎勵與常數（`config.ts`、`rewards.ts`） |
| `application/` | 自動教練、比賽執行、放置時間、批次、結算、領取、升級／招募／釋出（`economyService.ts`）、晉級挑戰（`leagueService.ts`）、進行中比賽的固定計畫與直播排程（`liveMatch.ts`、`livePlayer.ts`）、精彩時刻判定（`matchMoments.ts`）、比賽時間軸（`replayPlayer.ts`）、建立／重設／遷移入口（`clubLifecycle.ts`）、目前建議（`guidance.ts`）、新手任務旗標的寫入（`onboardingService.ts`） |
| `infrastructure/` | localStorage 存檔、Web Locks、依賴組裝（`createV2Deps`）、系統時間 |
| `ui/` | 控制器（不依賴 DOM）與各個畫面；觀戰畫面 `replayView.ts`（直播、挑戰賽）是動態載入的獨立 chunk，使用共用的 `src/ui/playAnimation.ts`、`FieldRenderer`、`PitchCam`；網站入口 `entry.ts` |

設計決策見 ADR-0007（自動比賽）、0008（放置結算）、0009（可玩 MVP）、0010（養成、招募、經濟、遷移）、0011（聯盟晉級、釋出球員、V5 遷移）、0012（即時觀戰、固定比賽計畫、Box Score、V7 遷移）、0013（新手引導、首頁層級、目前建議、V8 遷移）、0014（直播精彩時刻、結果揭露時間、關鍵打席）、0015（聯盟對手強度每級 +0.4，Phase 6C 平衡調整）、0016（移除 V1、網站只有 V2、共用模組與 V1 舊資料的處理）、0017（招募市場：三選一、確認簽約、價格調整）。平衡分析見 `docs/balance/v2-phase6c-report.md`。

## 存檔

- localStorage key `dice-baseball.club.v3`，目前是 schemaVersion 8。舊的 schemaVersion 3～7 會在進入 V2 時自動升級，原始文字依來源版本備份在 `dice-baseball.club.v3.backup-schema3`～`…backup-schema7`（已經有別的球團的備份時不覆寫，改存到帶 revision 的 key）。
- 進行中的比賽：任何修改球團的操作都會先把這一場的計畫固定下來（`liveMatch`），所以已經開始的比賽不受升級、換陣容、晉級影響，新設定從下一場生效。
- 每場戰報有 Box Score（約 0.4 KB），保留最近 50 場；完整 Replay 只保存最近 3 場與最近一次晉級挑戰賽；觀戰不寫入存檔。
- 新手任務：能從既有紀錄推導的（第一場、培養球員）不另外存；存檔只多 `onboarding` 四個布林值（看過直播、領過收益、改過陣容、收起），約 80 bytes。觀戰時只在第一次記一次旗標，打開首頁不寫入。
- V1 時期的 key（錦標賽、球團史、自訂隊伍、教學、隊名等）不讀、不寫、也不刪除；只沿用頭像（貓／狗、裝扮）與音效開關這三個顯示偏好。詳見 ADR-0016。
- 所有寫入都在 ClubLock（Web Locks）內「讀最新存檔 → 計算 → 存檔」，並有 revision 檢查；不支援 Web Locks 的瀏覽器同一時間只允許一個分頁寫入。

## 指令

| 指令 | 用途 |
|---|---|
| `npm run test` | 全部測試（模擬引擎、共用元件、V2） |
| `npm run build` | 型別檢查並打包 |
| `npm run bench:v2` | 單場模擬效能 |
| `npm run bench:v2:idle` | 放置結算效能、存檔大小、滿員 30 人的升級與招募耗時、最高聯盟長期遊玩的挑戰／釋出耗時與存檔大小、Box Score 與 Replay 大小、固定計畫與直播時間軸的耗時、首頁目前建議與新手任務的計算耗時、精彩時刻判定的耗時 |
| `npm run balance:v2:matrix` / `:analyze` / `:report` | Phase 6C 的平衡模擬：策略 × 登入頻率 × 種子的矩陣（可分片、可接續）、成長曲線／招募／新手 24 小時／升級效益對照實驗、把結果整理成 Markdown；參數見 `docs/balance/v2-phase6c-report.md` 第 17 節 |
| `npm run balance:v2` | 養成、招募、經濟、聯盟晉級的平衡模擬（4 種玩家策略、30 天、3 個種子）；可用 `SESSIONS`（每天上線次數）、`DAYS`、`SEEDS=101,202` 調整 |

## 調整數值

- 比賽獎勵：`src/v2/domain/config.ts` 的 `REWARD_CONFIG`
- 升級成本、成長幅度、招募成本、人數上限：`src/v2/domain/progressionConfig.ts`
- 聯盟名稱、對手強度、收益倍率、晉級獎勵、晉級條件、挑戰對手強度、失敗冷卻：`src/v2/domain/leagueConfig.ts`

改完先跑 `npm run balance:v2` 看各策略的進度與勝率；改成長公式會影響之後所有比賽，但已經打完的比賽不會變。
